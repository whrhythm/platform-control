# C 可用助手与分享管理

2026-11-08。状态：实施中，尚未部署或通过本轮 UI 验收。

## 本轮完整任务

创建者发布助手后，从项目的发布与分享管理邀请已注册成员；成员在“可用助手”接受邀请并使用固定版本。创建者可调整应用及成员累计预算、设置到期时间、撤回分享。成员不能修改、删除或再分享助手，但继续管理自己的项目。

## 契约与兼容

- 新增独立使用目录：系统编程助手、我发布的、分享给我的。只有启用且具有正式版本的业务助手出现在可用项；待接受邀请单独展示，不当作可调用助手。草稿和私人试用继续在项目维护。原生旧助手、会话不删除、不自动转换为正式发布。
- OpenHands 为系统开发入口，沿用当前模型/工作目录/审批配置，无删除入口；它不是用户交付的正式业务助手。公共审核目录不在本批开放，不把原生公开 Agent 当作平台正式审核成果。
- 既有有效成员迁移为已接受，保留使用权；新分享 pending → active，拒绝/撤回/到期后不允许新调用。重新邀请需当前修订并再次接受，不自动恢复被撤回的权限。已发送的调用可完成结算，撤回后禁止下一次模型与知识调用；保留旧聊天记录。
- 创建者是付费主体。成员上限属于应用总预算内的累计消费限制，不是充值或转账；所有正式版本合并统计该成员的已结算和在途/未知占用。降低到已占用以下会阻止新调用，但不清零或篡改费用。未单独设置的旧成员继承应用总上限。
- 所有变更经过服务端所有权核验并审计。并发额度预占与分享变更沿用创建者环境锁；成员编辑使用修订号避免覆盖。账号不存在/未满足邀请条件返回统一错误，不透露账号敏感状态；重复邀请不重复建对象或重置消耗。
- 显示名称来自已发布时的项目名称快照；原文、私有配置、凭据和开发项目不在目录返回。历史发布缺少名称快照时只兼容读取项目名。
- 增量迁移增加成员状态、修订、到期及额度字段；保留全部 ID、会话、快照、账本。后端先部署，前端后部署；旧客户端不得绕过新邀请确认与成员限制。

## 验收清单

- 发布前不入使用目录；发布后本人可见，未邀请账号不可见/不可调用。
- 未知账号、重复邀请、接受/拒绝、过期、撤回、再次邀请、过期页面保存冲突。
- 成员上调/下调额度，耗尽拒绝、并发预占、撤回在途结算，已用额度保持。
- 成员 UI 无编辑/删除/分享；原生与直接接口拒绝，成员仍能创建/维护自己的项目。
- 已有会话保留、旧版本固定、新版本新会话生效；浏览目录不改变聊天或草稿。
- 亮/暗/手机界面，失败重试；接口、迁移、PostgreSQL 并发测试、构建/类型检查；指定创建者及已授权合成成员真实流程。
