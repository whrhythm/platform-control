# 本轮需求与人工验收协议

每份记录绑定当前用户的一个编程任务及其工程目录，不代表项目后续修改或线上应用已验收。系统执行证据与人工验收分开显示。

## 接口与保存

- GET `/internal/v1/workspace/agent/tasks/{id}/acceptance`：只读，无记录返回 revision 0，不创建数据。LibreChat 通过已登录身份桥接，浏览器不可指定所有者。
- PUT 同路径：`revision`、`goal`（最多 4000 字符）、`criteria`（最多 12 项，每项 UUID、最多 400 字符的 text、result 为 pending/passed/changes_requested）、`note`（最多 1000 字符）。所有字段均严格校验，未知字段拒绝。
- 任务 resources 中增加版本为 1 的 acceptance 对象，内容使用既有平台密钥加密；仅摘要计数与修订号明文。不增加数据库表，不改 AgentConfig 或 CapacityPlan；现有工作器通过保留 resources 其他键保持兼容。
- 保存锁定任务行并比较修订号。相同上一修订号及相同内容可安全重试；不同内容返回 409，不能覆盖另一页面的修改。审计只记录任务 ID、修订号和操作者，不记录需求或验收正文。
- 修改目标、新增或修改验收条件时，对应结果必须重置为 pending；修改整体目标时全部重置。运行中的任务可以整理条件，但不能记录验收结果。用户的 passed 不会更改 Agent 执行状态，也不会触发发布。

## 原始需求与证据

新任务单独加密保存最后一条用户消息，最多 4000 字符，截断时明确标记。系统提示和之前的对话不作为本轮需求返回。旧任务没有独立需求时显示可补充，不猜测或从混合提示中截取。

文件摘要仅列已记录成功的 write/mkdir 操作；通过命令修改的文件不一定出现在该列表，因此不能称作完整源码差异。命令退出码为 0 仅表示执行成功，不等于业务测试通过。已有命令输出和文件记录保留供核对。人工验收与平台就绪检查、发布成功互不替代。

本批保留当前人工验收记录和每次保存的审计元数据，不提供验收正文的历史版本对比。下一轮任务不继承上一轮的 passed。记录正文不会提供给共享聊天或模型工具身份。
