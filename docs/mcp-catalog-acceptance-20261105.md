## 真实界面流程

管理员账号仅用于 MCP 配置验收：从界面创建临时服务，地址使用公开 DeepWiki，发现工具后只批准 `read_wiki_structure`，审核并发布。该连接具有新生成的服务 ID，未写入代码固定目录。

使用用户指定的普通账号，在原有测试对话的编程设置中选择这条动态连接，开启只读工作方式，发送公开仓库文档查询。在聊天点击确认后，真实 OpenHands SDK 经独立网关取得工具结果；最终答复直接显示在聊天。任务恰好一次 `mcp_started` 和成功 `mcp_result`，没有文件写入或终端操作。

检查亮色与暗色界面后，恢复原有编程偏好及亮色主题。管理员随后从界面停用并归档临时服务，保留六条对应管理审计。内置 DeepWiki 通过同一检查与审核流程更新为数据库目录，保留三个只读工具，并记录其真实定义指纹。

截图、测试会话定位及浏览器辅助脚本保留在被 Git 忽略的 `release/` 中。没有将用户聊天或界面内容提交 Git。没有修改用户工程文件、创建应用、发放额度或更改套餐。

## 验证范围与限制

动态管理流程及公网无凭据调用已在集群真实验证。用户专属和平台专属 Bearer Token 的隔离、撤销及授权通过本地测试验证；未持有其他供应商的真实私有账号，因此不声称已经验证所有供应商或真实私有服务写入。

本版不支持 OAuth 授权跳转、旧式 SSE、私网地址、任意本地命令。服务参数结构必须通过受限 JSON Schema 校验；DNS 公网地址或已批准工具定义变化需重新审核。

Lighthouse 已尝试，本地准备脚本因缺少 `rimraf` 可执行入口未启动，不能声称通过性能门禁。Postman CLI 1.74.0 没有 `status` 子命令，模拟证据来自真实 HTTP 运行和调用次数断言；未发布到 Postman 云空间。
