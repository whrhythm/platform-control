# P1-03 固定草稿试用与验收

2026-11-07。实施中，本文不是已交付证明。用户任务：配置知识助手，打开固定版本预览，核对回答及来源，记录验收；修改后开启新版本试用，旧会话仍使用原配置。

## 实施契约

- 项目版本设置由 Platform Control 保存。首次进入时从同一所有者的现有私人 Agent 导入指令/模型；不覆盖原生 Agent，也不改动原会话。后续项目草稿在项目入口编辑，旧原生 Agent 的独立修改不自动覆盖受控草稿。
- 草稿包含指令、明确模型、温度、输出上限和受控答复 Skill。首批只允许知识检索和内置答复规范；任意 MCP、原生动态 Skill/子 Agent 不混入固定预览。
- 当前指令、模型路由标识、Skill 内容与当前就绪知识修订组合成摘要。知识变化自动使旧验收失效。快照沿用 P1-00 AgentSnapshot 契约，原文/配置加密保存。
- 打开预览先保存幂等意图，再按稳定 ID 创建私人原生 Agent 作为聊天入口。每次执行从服务端读取不可变快照；浏览器/原生编辑器不能覆盖实际运行配置。
- 会话首次执行绑定用户、项目和试用快照，后续请求不得跨版本切换或借用原对话。模型密钥仍为创建者本人的现有额度，受邀代付在 P1-04。
- 每轮执行重新检查账号、模型和知识状态。被删除的知识立即拒绝后续检索，不因试用快照存在而保留访问权。
- 验收需要实际保存的本人试用回答及人工结果，记录会话、回答 ID、内容摘要和说明。模型自述通过不等于验收。指令/模型/知识变化后旧确认仍作为历史保留，但不再有效。
- 超时、刷新或重试不自动重发模型问题；沿用原生会话恢复。预览准备结果不明按稳定 ID 查证，不重复创建 Agent。

## 验收范围

验证旧会话使用旧指令/知识、新预览使用新版；伪造身份/会话/覆盖参数被拒；知识删除、模型撤销、配置并发修改与丢失回包可解释；验收只能关联已保存的真实助手回答。通过指定账号执行三轮配置→预览→修改→再次预览→验收，并回访亮暗主题与现有文件/应用入口。

正式发布、最终使用者入口与代付不在本步骤内。现有原生私人 Agent 聊天不自动被认定为固定版本验收。
