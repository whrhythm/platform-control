# P1-03 固定草稿试用与验收

2026-11-07。核心功能已实现、部署并通过指定账号 UI 验收；性能与商业稳定性门槛尚未通过。用户任务：配置知识助手，打开固定版本预览，核对回答及来源，记录验收；修改后开启新版本试用，旧会话仍使用原配置。

## 实施契约

- 项目版本设置由 Platform Control 保存。首次进入时从同一所有者的现有私人 Agent 导入指令/模型；不覆盖原生 Agent，也不改动原会话。后续项目草稿在项目入口编辑，旧原生 Agent 的独立修改不自动覆盖受控草稿。
- 草稿包含指令、明确模型、温度、输出上限和受控答复 Skill。首批只允许知识检索和内置答复规范；任意 MCP、原生动态 Skill/子 Agent 不混入固定预览。
- 当前指令、模型路由标识、Skill 内容与当前就绪知识修订组合成摘要。知识变化自动使旧验收失效。快照沿用 P1-00 AgentSnapshot 契约，原文/配置加密保存。
- 打开预览先保存幂等意图，再按稳定 ID 创建私人原生 Agent 作为聊天入口。每次执行从服务端读取不可变快照；浏览器/原生编辑器不能覆盖实际运行配置。
- 会话首次执行绑定用户、项目和试用快照，后续请求不得跨版本切换或借用原对话。模型密钥仍为创建者本人的现有额度，受邀代付在 P1-04。
- 每轮执行重新检查账号、模型和知识状态。被删除的知识立即拒绝后续检索，不因试用快照存在而保留访问权。
- 验收需要实际保存的本人试用回答及人工结果，记录会话、回答 ID、内容摘要和说明。模型自述通过不等于验收。指令/模型/知识变化后旧确认仍作为历史保留，但不再有效。
- 超时、刷新或重试不自动重发模型问题；沿用原生会话恢复。预览准备结果不明按稳定 ID 查证，不重复创建 Agent。

## 验收范围

验证旧会话使用旧指令/知识、新预览使用新版；伪造身份/会话/覆盖参数被拒；知识删除、模型撤销、配置并发修改与丢失回包可解释；验收只能关联已保存的真实助手回答。通过指定账号执行三轮配置→预览→修改→再次预览→验收，并回访亮暗主题与现有文件/应用入口。

正式发布、最终使用者入口与代付不在本步骤内。现有原生私人 Agent 聊天不自动被认定为固定版本验收。

## 使用手册

1. 打开「我的空间 → 项目」，在 AI 项目卡片中展开「配置与预览」。老项目首次点击「导入现有助手配置」，导入当前私人助手的指令和模型。此操作幂等，不覆盖已有受控草稿。
2. 「修改配置」可调整助手指令、允许使用的模型、回答多样性、单次输出 token 上限，以及两种内置答复规范。保存时检查读取的草稿摘要；另一页面修改了草稿或知识时会拒绝覆盖。需要保留编辑内容时先复制，再取消编辑载入最新草稿。
3. 点击「创建固定预览」。准备完成后在对应的「试用版本 N」点击明显的「打开预览」。进入原有聊天界面，顶部助手名称包含试用编号。可直接提问并展开检索结果查看该版本的资料原文。
4. 试用回答保存完成后，回到该项目的「配置与预览」。必要时点击「刷新试用状态」，在本次版本下选择「验收当前对话」，核对回答和来源，填写说明，记录通过或需改进。未完成、停止、出错或手工伪造的回答不能用作通过凭据。最终判断仍由人负责，系统不能证明人的验收结论正确。
5. 修改指令、模型、内置规范或项目知识后，旧记录变成历史验收，不再代表当前草稿已通过。创建新预览后重新测试。旧对话保持原指令、模型参数和知识修订，不自动升级。
6. 「继续试用对话」回到该版本最近的会话。新会话不携带开发聊天；已有试用会话不允许切换其他版本。不要通过原生 Agent 编辑器调整试用配置，执行时以项目固定快照为准。

注册赠额、付费权益及当前个人 LiteLLM key 沿用已有规则。创建预览本身不调用模型；实际发送问题才进入原有模型计费链路。受邀用户和创建者代付尚未开放。

## 持久化与执行边界

- Alembic `0025_ai_project_trials` 新建草稿、固定试用、会话绑定与执行回答标识四张表。已有用户、文件、应用、套餐及知识表不重写。试用指令和人工说明加密保存，审计仅存动作及目标标识。
- 每次实际运行在控制面绑定服务端回答 ID；验收 BFF 读取同一所有者的 MongoDB 已保存对话与完整回答，计算摘要，控制面再验证回答 ID 属于这次运行。不接受浏览器提供回答正文、摘要、所有者或模型调用凭据。
- 知识检索从首次调用就使用固定修订；不回退到最新索引。移除知识后旧试用不能继续检索。草稿修改不会删除旧资料或用户文件。
- 平台运行状态和当前权限属于实时服务端边界：即使资料写有“发布 v2”，也不能据此认定试用已经上线。固定的是用户配置、受控 Skill 内容及知识修订，不是锁死平台安全规则或供应商模型实现。模型路由摘要标识配置的网关地址，不能证明上游供应商永久不更新模型。
- 两种内置 Skill 是受控回答规范，不是通用原生 Skill/MCP 市场。试用只允许项目知识工具，不把普通聊天项目的额外指令、临时文件、动态 Skill、子 Agent 或代码工具带入快照。
- 当前每项目最多 50 个试用版本，输出上限 4096 tokens；管理员可通过 `PLATFORM_AI_TRIALS_LIMIT` / `PLATFORM_AI_TRIALS_OUTPUT_LIMIT` 调整。版本历史没有自动删除；归档和有保留依据的清理后续实施，不以回收任务为由删除用户资料。
- 运行请求超时不自动重发，继续沿用原生会话持久化和恢复；创建失败按确定的 ID 恢复。已经绑定但被删除的原生 Agent 不会由重试擅自复活。每个试用只保存一个不可覆盖的人工验收决定，进一步验收另建试用。
