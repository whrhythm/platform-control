# 管理控制台与体验套餐配置

管理入口按职责分为“套餐与配额”“模型与结算”“用户与资源”“待核验”“MCP 服务”。不再提供旧的个人空间创建、项目申请和资源规划表单。普通用户从 LibreChat 使用自动开通的个人空间。

## 汇率和预算

“1 美元 = 7 元人民币”表示平台结算汇率。售价与模型额度独立：售价 10 元、模型额度 5 元时，LiteLLM 美元预算增加 floor(5 / 7 × 1,000,000) / 1,000,000，即 0.714285 美元。页面预估保留六位小数，订单按微美元向下取整。已有订单保留创建时的汇率和额度，不追溯修改。

## 体验套餐

选择“体验版”，可以编辑逻辑总容量、单应用 CPU/内存、应用总配额、数据库额度、编程/构建额度及聊天运行代码次数、时限、并发等。高级资源组折叠显示摘要，展开后编辑。注册一次性赠送 1 美元预算仍是固定规则，独立于这些资源权益，不能将体验套餐作为充值订单购买。

保存配置 → 后续新用户首次登录 → 在一个数据库事务内创建用户环境、权益快照及开通意图 → 后台创建独立命名空间和持久卷 → 用户界面读取实际生效的权益。

已有用户的权益快照不被修改。重复登录不重置容量、不重复发放赠金；旧用户缺少权益记录时仍走原有兼容回填，不能领取新目录权益。需要调整已有用户时，应走明确的权益调整/订单流程，本页不批量覆盖老用户。

## 接口约定

- `GET /v1/admin/ai` 的 `policy.trial_plan` 总是返回完整、已校验的体验资源套餐。
- `PUT /v1/admin/ai` 接受 `trial_plan`；ID 必须为 `trial`、CNY、售价和人民币充值额度均为零。资源上下限及交叉约束与付费套餐相同。
- 旧客户端不提交该字段或提交 null 时保留原体验配置；不会重置为系统默认。并发修改仍用 revision 校验；管理员保存写入现有审计记录。
- 体验套餐不能出现在可购买的 plans 目录中。
- 新用户的环境和 CapacityAccount 同事务创建；唯一身份约束应对并发首次登录。项目环境旧接口也保存相同权益快照。
- `/internal/v1/workspace/capacity` 的 `plan` 是已开通快照；`trial` 是当前新用户体验目录。两者不混为当前用户权益。
- 不改变 LiteLLM API、充值流程和赠金逻辑；没有新增外部 HTTP 依赖。

## 命名空间与存储

命名空间按已验证的 issuer + subject 生成稳定标识，同一用户的各项目使用同一独立命名空间。其内有独立的 `workspace-data` PVC、ResourceQuota、默认拒绝网络策略和经过批准的访问规则；用户应用在相同命名空间中。空间通过首次登录自动准备，删除旧管理表单不删除命名空间、磁盘或文件。命名空间本身并非完整安全边界，还需要身份鉴权、网络策略及执行任务的隔离运行时。

## 发布与验收

先升级 agent-worker、MCP、工作空间、计费、存储和发布等读取配置的后台服务，再升级 API/管理页面，避免旧服务读取新字段报错。验证实际后台的配置解析和真实编程任务。

自动测试覆盖管理员权限、修订冲突、错误配额、兼容旧客户端、新用户快照、重复登录不覆盖权益、不同身份空间不同、旧项目接口一致性。PostgreSQL 并发测试运行于本机临时数据库，不操作生产用户数据。浏览器检查套餐切换、折叠组、汇率解释、保存、窄屏和 1440px 对齐；管理员验收仅使用 akadmin 查看和保存配置，普通用户验收使用已指定账号。
