# P1-01 私人 AI 项目绑定

日期：2026-11-06。当前为实现和部署验收记录；状态以本文后续追加的实测结果为准。

## 用户路径

LibreChat「我的空间 → 项目」增加 AI 项目入口，填写名称和业务用途后，创建属于当前用户的私人业务助手。用户可直接试用助手，或打开关联的文件目录；聊天主界面、已有文件和应用不迁移。此时知识明确标记「尚未配置」，不宣称已具备 RAG 或正式发布。

## 保存与恢复

浏览器生成请求 ID，身份由 LibreChat 服务端取自已认证的 OpenID 用户。控制面锁定当前用户空间，持久化项目及绑定意图，按请求 ID 生成稳定的项目和 Agent ID。重复请求核验同一记录，不重复创建。LibreChat 依次准备目录、核验或创建私人 Agent、授予原生 owner 权限，最后回执控制面。

中断时保留 preparing 记录，用户刷新后能继续准备。恢复不会覆盖已有助手配置、已有文件，也不会重新创建已绑定后删除的助手或恢复后来撤销的权限。账号与权限校验仍在服务端执行。没有跨 PostgreSQL/MongoDB 的虚构原子事务，也不靠人工改库修复状态。

配置：`PLATFORM_AI_PROJECTS_ENABLED` 默认 false；LibreChat `aiProjects.requestTimeoutMs` 默认 35000 毫秒，控制单次上游请求。AI 项目复用当前用户的项目数量上限；不新增收费和自动共享。

## 数据与部署

Alembic `0023_ai_project_bindings` 新增绑定表，不修改现有业务表数据；API 角色需取得该表 SELECT/INSERT/UPDATE 权限。新增配置不改变 CapacityPlan，不要求重启执行任务的 worker。已有消费者继续读取原表。

迁移前保存数据库备份。先部署兼容新 schema 的 API，再启用入口。迁移后关闭功能可禁用入口；旧 API 的 schema 启动检查不兼容 0023，因此回退使用本批 API 加关闭开关，不回滚到 0022 镜像。表中存在绑定记录时拒绝破坏性降级。

## 下一步 RAG 决策

知识导入属于 P1-02。优先评估 LibreChat RAG API、专用 pgvector 存储和可用的中文嵌入模型，先核验版本与实际资源消耗，再决定部署版本。当前只有聊天模型，不能把它当嵌入模型。单节点组件使用明确 CPU/内存/存储上限，无需为首个知识助手引入工作流引擎。

不能仅配置全局 RAG 地址就开放所有上传：知识应由项目明确选择，文件、索引、检索均绑定服务端所有者和项目，导入计入逻辑容量，失败有界且可恢复。首批限 MD/TXT 小资料，版本更新不能替换已发布引用的旧索引。界面接入、容量、权限和回答引用均验收后才标记知识可用。
