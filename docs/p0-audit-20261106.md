# 星桥 P0 现状核查与首发范围

核查日期：2026-11-06，主要线上读取为北京时间 19:15—19:23。产品依据为[产品纲领](product-charter.md)。本轮只做代码、部署与指定账号的只读界面核查，没有创建 Agent、发送模型任务、更新项目、充值、迁移数据库或部署镜像。

## 1 结论

现有系统具备开发与托管基础：用户登录、持久文件、OpenHands 编程、代码运行、应用发布、项目数据库、权益与管理员治理均有实现及历史验收记录。本轮确认主要服务运行，用户入口、文件空间及相关读取接口可用。

**尚未形成纲领要求的可交付 AI 应用闭环。** 最关键的缺口是知识检索未启用、项目与业务 Agent 未统一关联、缺少隔离草稿和线上配置的发布流程，以及应用使用者身份与费用承担尚未贯通。

后续复用 LibreChat 原生 Agent 与 Skill 基础，扩展项目绑定和版本交付，不重建完整聊天/Agent 平台，不先引入 Dify/Langflow。OpenHands 继续作为开发助手，为业务 Agent 补充必要代码；它不自动成为交付给最终用户的 Agent。

P0 的现状、首发范围、交互草图、实施清单与固定验收数据已整理。当前可以进入 P1 的契约与依赖验证任务；**不能据此认定 P1 已完成或产品可商业上线。**

## 2 证据口径与部署基线

- **C：代码证据**，能定位实现或缺口；不代表已部署或真实调用通过。
- **D：本轮部署证据**，观察到服务、镜像或生效配置；不代替业务验收。
- **U：本轮用户读取证据**，仅指定账号的登录、界面与 GET 接口；不代表新建、修改或跨用户测试通过。
- **H：历史验收证据**，保留原版本、环境和范围；本轮未重新执行其写入流程。
- “未完成”指新产品闭环存在缺口；“未验证”指可能有实现，但没有本轮或适用场景的充分证据。二者不混用。

## 4 最重要的代码判断

### 两类项目与两种 Agent

控制面 [`WorkspaceProject`](../control_plane/models.py) 的主要字段是 owner environment、project_path、name、goal 与 revision。LibreChat 的 [`chatProject`](../../LibreChat/packages/data-schemas/src/schema/chatProject.ts) 和[聊天项目上下文](../../LibreChat/packages/api/src/projects/context.ts)另有 instructions 与文件资源。当前[项目界面](../../LibreChat/client/src/components/CodeChat/Projects.tsx)未统一关联业务 Agent。后续采用明确的 ID 映射，不能自动合并已有项目或移动文件。

控制面 [`AgentTask`](../control_plane/models.py) 是编程执行任务；LibreChat [Agent schema](../../LibreChat/packages/data-schemas/src/schema/agent.ts) 才具有业务对话的指令、模型、工具、Skill 与历史版本基础。两者共存，各司其职。

### 有版本历史不等于发布隔离

LibreChat [loadAgent](../../LibreChat/packages/api/src/agents/load.ts) 当前持久 Agent 路径按 ID 读取记录；版本数作为元信息，不是读取一个固定的已发布快照。控制面的[发布溯源](../control_plane/release_provenance.py)主要冻结任务验收、源码和镜像证据。因此必须补“草稿可修改、线上仍使用指定版本”的服务端约束，不能只增加一个发布按钮。

### 有文件不等于有知识库

[文件检索](../../LibreChat/packages/api/src/files/rag/search.ts)依赖 RAG 服务，支持用户/Agent 范围与引用；[RAG 文件管理](../../LibreChat/packages/api/src/files/rag.ts)另有索引所有权与删除逻辑。上线缺依赖时不应承诺可检索。普通附件全文上下文与可维护知识库也不是同一种功能。

### 权限与费用不能沿用开发者身份冒充最终用户

[当前模型代理](../control_plane/programming.py)与[LiteLLM 映射](../control_plane/litellm.py)以用户凭据识别环境与预算。未来业务调用须同时记录调用者、应用所有者、项目、发布版本和使用目的，由服务端决定代付授权；不能把创建者密钥发给受邀用户，也不能默认消耗受邀用户的注册赠额。

这是 P1/P2 的实施范围，不是现有支持声明。

| 维度 | P1 知识助手 | P2 售后 AI 助手 | 暂不承诺 |
| --- | --- | --- | --- |
| 交付形态 | 一个项目对应一个主要对话应用，浏览器使用 | 在同一应用上增加工单操作和必要配套页面 | 任意工程即时运行、独立游戏/商城搭建 |
| 知识来源 | 用户显式导入 UTF-8 Markdown/TXT；展示索引状态、来源与引用 | 延续相同来源，增加业务记录查询工具，不把数据库自动当知识库 | 网页爬虫、OCR、扫描 PDF、自动连接所有云盘 |
| 初始知识限制 | 配置化上限：每应用 10 个文件、单文件 1 MiB，且受实际剩余存储约束 | 按实测再调整，不能暗中扩容 | 无限文件、无限上下文；上限是初始产品约束而非已实现值 |
| Agent 与模型 | 复用原生执行基础，管理员允许的真实模型；中文默认行为 | 延续，支持受控业务工具 | 任意模型都兼容工具调用或长上下文 |
| Skill | 首批一个审核过的文本“有依据回答”技能，固定版本，不附带新权限 | 加入工单操作说明与审批规则 | 任意可执行包、市场和自由安装依赖 |
| 工具 | 知识检索；新发布应用默认不开放 shell/代码运行/任意 MCP | 经服务端授权的建单/查单，写入确认与幂等 | 直接继承创建者所有 MCP、文件或部署权限 |
| 试用 | 草稿测试对话、回答依据和公开执行结果；与正式会话分开 | 测试工单数据与真实记录分开，页面真实调用测试后端 | 将离线示例页面称为完整后端验收 |
| 发布与访问 | 固定版本、受邀且已登录用户、独立使用入口；初期沿用内网域名和 TLS 条件 | 同一身份规则覆盖工具和配套页面 | 公开匿名使用、每应用自定义域名、EdgeOne 集成 |
| 费用 | 创建者账户承担经授权的测试与应用模型调用，区分用途与预算 | 增加工具操作及配套运行资源归属 | 真实订阅收款、向终端用户自动收费 |
| 数据保护 | 仅合成资料；索引、源码与会话的保留边界明确 | 合成工单，验证修改后的持久性 | 缺独立备份时接收真实重要业务数据 |

首发受邀使用者登录不等于成为创建者；需要校验现有登录开通逻辑，并设计仅使用应用的访问路径。邀请开通、注册赠额和独立磁盘不应混为一件事。

## 6 用户路径草图

```text
创建者：我的空间 → 新建 AI 项目 → 描述用途 / 导入知识
        → 同一项目聊天区：继续提需求、查看生成与索引反馈
        → 打开预览：测试对话、检查引用、查看公开工具结果
        → 继续修改 → 刷新草稿 → 确认访问范围与费用 → 发布
        → 返回项目：线上版本 / 未发布修改 / 用量 / 反馈

使用者：受邀链接 → 登录与授权检查 → 该应用的对话入口
        → 提问 / 交办任务 → 看到答案、引用和真实业务结果
        （不进入开发聊天、个人工程、模型密钥或发布管理）

管理员：现有控制台 → 处理权限、知识索引失败、额度与异常
        （不接管用户日常创建与发布操作）
```

保留主聊天区域。项目头部只显示项目名称、草稿/已发布状态、预览与发布入口；知识与进阶设置按需打开。预览侧区首先是业务助手测试会话，有配套页面时再切换页面视图。文件和已有应用继续可达，不再围绕 HTML 文件决定布局。

## 7 风险优先级与工作处置

1. **P1 阻塞：** 检索服务/嵌入链路缺失；项目—Agent 关联缺失；草稿/发布快照缺失；受邀使用与费用承担缺失。这四项属于同一纵向闭环，不能只完成配置 UI。
2. **P1 前须验证：** 原生 Agent 使用现有模型代理的工具调用兼容性、引用传播、权限校验和用户密钥供给。能力列表有 `file_search` 不等于实际运行成功。
3. **P2 前须收口：** 原生 MCP 与平台 MCP 目录的治理边界；已有应用账号与平台受邀用户的授权映射；工单工具的幂等键与未知写入处理。
4. **商业阻塞：** 独立备份、真实数据恢复、多身份验收、真实支付和运营证据。当前不满足，不在文档中改写成已具备。
5. **旧改动处置：** HTML `Preview.tsx`、`project_preview.py`、静态构建方案保留未提交，不部署；源码核对思路可复用，但将来版本确认范围必须覆盖 Agent/知识/工具配置。本轮不删除或混入新功能提交。
