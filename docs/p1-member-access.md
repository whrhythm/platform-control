# P1-04A 受邀应用仅使用权限

2026-11-07。依据[产品纲领 v1.1](product-charter.md)与用户本次恢复开发指示实施。此记录区分设计、实现、部署和真实验收；未完成的门槛不算通过。

## 用户任务与边界

受邀成员使用发布的 AI 助手，不能编辑、删除、复制、重新分享运行入口，也不能读取完整配置和版本历史。成员仍可创建和管理自己的项目与原生智能体。应用的访问权限和预算由创建者管理；OpenHands、聊天、个人文件不因此改版。

## 权限修复契约

- `agent_app_<固定编号>` 是服务端创建的正式应用运行入口，沿用已有编号和成员的会话绑定。其 `author` 字段用于记录收件成员，不能推导管理权。用户新建普通智能体由服务端生成其他编号，不能指定保留编号。
- 新入口只授予对应成员原生聊天 VIEW 权限，不授予 owner/editor、共享或远程 API 权限。每次启动入口重新核验；应用停用、成员撤销、固定版本与创建者代付仍走已有控制面检查。
- LibreChat 启动接收请求前执行幂等权限修正：仅处理正式运行入口的 ACL，移除旧的所有权、远程访问和额外共享，仅保留成员私人 VIEW。修正失败不带错权限启动。新旧版本采用现有 Recreate 发布方式，避免旧进程重新写入 owner。
- 原生编辑、删除、复制、回退、头像和工具修改、完整配置与版本历史，在原生权限检查前拒绝；按 Mongo 资源编号访问通用分享接口也拒绝，不允许管理员旁路在原生界面改此托管入口。机器管理路由同样拒绝此编号，列表排除正式入口。
- 构建器列表排除正式入口；从已有应用会话打开构建器时显示“已发布应用 · 仅供使用”。不显示编辑字段或管理按钮，同时保留创建个人智能体的入口。界面拦截不替代接口鉴权。

## 数据与回退约束

不重建 Agent、不改写会话、消息、文件、试用或正式版本，不改成员身份、创建者付款方和未知费用预占。迁移前备份 MongoDB；上线后先比对 Agent/会话/消息/文件数量与内容摘要，再执行新增验收操作。备份位于同一主机，只能用于操作回退，不能抵御整机故障。

不能直接回退到重新授予 owner 的旧版本。若需回退，必须保留本批服务端拒绝与私人 VIEW 权限，或临时关闭正式应用入口；不能自动恢复旧的危险 ACL。已有文件和会话不因回退被删除。

### 真实账号与操作

使用用户批准的 `p104-member-20261107`、`p104-outsider-20261107` 合成账号；没有使用其他真实用户操作界面，也没有使用管理员旁路。

1. 成员直接请求原生入口的完整配置、版本历史、改名、复制、回退、头像、工具修改、删除，以及原生分享查询/修改和远程分享修改：11 项均为 **403**。额外请求创建者的发布列表、访问设置、邀请成员和草稿列表：4 项均为 **404**，按既有规则隐藏非本人项目。请求前后入口信息一致，实际权限查询为 `permissionBits: 1`。
2. 从旧应用会话打开“智能体构建器”，受邀正式入口不出现在选择列表，界面默认用于创建自己的智能体；列表中可找到成员新建的私人项目。没有把“创建”表单误认作编辑受邀应用。旧状态直接选择正式入口时的只读提示与按钮隐藏，由组件测试覆盖。
3. 同一成员在“我的空间 → 项目”创建 `P1-04A 成员自建项目`，导入并保存自己的助手草稿。随后在构建器选中自己的项目，修改名称、保存，再通过 UI 恢复名称，两次保存均成功。单独临时创建的原生智能体经接口完成创建、修改、权限读取和删除；没有删除与长期项目绑定的 Agent。
4. 旧会话刷新可见原有消息，续聊继续命中知识修订并保留旧版本“第3轮”标识；一次完整回答约 **6.49 秒**，不据此推算 p95。正式应用链接仍可“开始使用助手”；未获授权的合成账号启动请求为 **403**。
5. 亮/暗主题通过保存设置并重新加载后验证；列表、已有会话及自己的编辑控件可用。截图等待动画结束后保存，不把过渡帧当作最终主题状态。
6. 本次续聊对应两条模型调用均 completed；LiteLLM 对应消费 `0.0009483 + 0.0010557 = 0.002004 USD`，实际付款人为创建者，actor 与 sponsor 分离。成员累计模型消费仍为 0。旧版发布编号 1—3 和当前正式版指针保留，应用预算仍为 0.50 USD。

### 既有数据核验

部署后、产生新增验收操作前，**54 条会话、265 条消息、4 个文件记录**的数量和完整内容摘要与部署前一致。13 个 Agent 的编号、配置和版本均保留；三条正式运行入口已变为私人 VIEW，仅清理它们的旧管理/分享授权。

最初 Agents 整体摘要不同，已暂停后续测试并将备份恢复到独立库逐字段比对：差异只有一个既有自建项目 Agent 的 `updatedAt`，没有业务字段或版本变化。没有为消除差异回写数据库；不能声称所有数据库字节完全不变。之后新增的合成私人项目和续聊消息是验收操作的预期结果。

历史待核验费用没有释放或重写。最终观察为 2 条 uncertain、预占合计 7462 微美元，分别产生于本次部署前的 08:01 与 08:14 UTC；本批续聊的两条调用在 09:05 UTC 完成。此问题仍按 P1-05C 核验，不在权限修复中擅自退款或重放。

### 失败、人工干预与限制

- 首次构建被 TypeScript 阻止：lean 数据记录不能按完整数据库文档传入。缩小为身份字段类型后重建；失败镜像未部署。
- UI 验收脚本初次未识别已有 SSO 自动回跳；另一次未等待草稿加载就尝试编辑。均修正等待条件并续跑，没有重建测试项目或重复发送模型问题。头像负向测试初始路径错误，已改为真实 `/api/files/images/agents/:id/avatar` 并取得 403；错误路径的 404 不计权限通过。
- 费用日志的 attribution 位于序列化/嵌套 metadata，初始顶层字段查询未找到本次记录；解析白名单字段后按两条调用 ID 确认真实账单，没有修改账单。
- `npm run lighthouse` 已尝试，测试镜像缺少 `openssl`（`spawnSync openssl ENOENT`），未取得性能成绩。多日重复、故障矩阵与性能门槛仍属于 P1-05D。本次不是完整性能或商业稳定性验收。
- 没有外部独立评审和远端 CI 通过证据；上述构建门禁是在受控构建主机运行。备份仍在同一主机，不是异地灾备。
