# OpenHands 聊天反馈验收 — 2026-11-06

## 用户问题与实测原因

用户报告小游戏任务长时间没有文字和执行反馈。只读检查本次任务记录后发现：接单约 2 秒，首次公开文字约 3 分 32 秒，总任务约 12 分 8 秒。执行器原先只投影公开回答，模型生成工具参数和内部推理期间没有活动信号；界面又只显示最近一段公开说明。多轮检查进一步延长等待。

这些是本次具体任务的观测，不是平台平均耗时。没有把用户原始需求、源码、推理内容或身份凭据写入本文。

## 本次体验调整

1. 同一助手回复中增量展示公开文本，并保留之前的进度说明。
2. 活动状态区分思考、生成代码或操作、回复、准备执行、执行和等待审批；沿用普通聊天的动画、主题色与减少动画设置。
3. 工具参数只上报生成字符数，不展示内容；思考只上报活动状态。字符数不是 token 费用或完成百分比。
4. 显示耗时和最近保存文件，30 秒没有新事件时明确说明等待，不伪造执行进展。命令详情默认折叠，审批和停止仍在聊天内。
5. 已取消或失败任务保留部分回复并标记未完成；最终状态停止动画。刷新恢复同一任务，不重新执行。
6. 小型单页任务优先完成首版，避免自行安装浏览器或测试框架；明确临时文件应使用工程缓存目录，避免误写只读 `/tmp`。
7. 编程执行在普通聊天请求结束后仍可增长：聊天滚动跟随活动任务及最终结果，用户向上阅读时不强拉回底部。

## 真实浏览器验收

使用用户指定的验收账号，在独立 `chat-feedback-20261106` 文件夹，通过 LibreChat 编程设置和聊天输入框提交单文件坦克小游戏需求。未改动已有游戏或售后工单项目，也未发布测试游戏。

下载由该任务生成的文件，在独立浏览器上下文实际打开：开始按钮可用，方向键使玩家移动约 47 像素，空格输入可用并观察到子弹，R 重置位置、分数及生命；测试期间没有浏览器运行异常。此项验证单文件游戏，没有声称完成公网发布、所有游戏边界测试或多人并发测试。

这次首个可见反馈明显改善，但一次任务不能推导普遍的 4 秒首字或 4 分钟交付承诺。模型仍会花时间生成、修正和检查代码；状态动画仅解决可观察性，不能代替模型速度优化。

最终滚动修正版再次通过真实聊天提交同一项目的只读检查，约 83 秒结束。浏览器记录到公开回复从 746 字符增长至 807 字符，消息滚动位置随之增长，距底部保持 0；最终结果也停在底部。中途主动向上滚动后，读取位置保持不变。验收脚本首次点击“滚动到底部”遇到两个同名控件，修正为浮动按钮后恢复观察同一任务，没有重发。任务完成且没有写入源文件；临时文件使用约定的 `$TMPDIR`，所有命令正常退出。模型仍拆分了多次只读命令，此类往返开销仍有优化空间。
