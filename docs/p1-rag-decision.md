# P1-02 知识检索部署决策

日期：2026-11-06。状态：方案确定，组件尚未部署，不能视为知识检索已可用。

## 选择

采用 LibreChat 原生 RAG API + 专用 PostgreSQL/pgvector + CPU 中文嵌入模型。首选 `BAAI/bge-small-zh-v1.5`；首发范围是中文 Markdown/TXT 售后资料，英文混合文本另做评估，不承诺多语种效果。RAG full 镜像支持本地 Hugging Face 嵌入，lite 镜像不能据此假定支持；验证后把镜像和模型固定到具体摘要/修订，保存到 Harbor/受控模型存储。运行时不下载未固定的新模型，不启用模型远程自定义代码。

依据：LibreChat [RAG API 文档](https://www.librechat.ai/docs/configuration/rag_api)说明其独立服务、pgvector 依赖及本地嵌入配置；BAAI [模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)列明中文定位和 MIT 许可。组件选型是本项目决策，响应性能和业务正确率必须实测。

不引入 Dify、Langflow 或第二套知识管理界面。业务数据所在的现有共享 PostgreSQL 不切换镜像；向量数据库用单独的有界实例，避免为安装扩展影响现有工单和控制面。

## 单节点初始资源预算

以下是拟部署上限，不是已经测得的消耗；部署前复查节点与存储余量。

| 部件 | 请求 | 上限 | 持久数据 |
| --- | --- | --- | --- |
| RAG API 与 CPU 嵌入 | 250m / 512Mi | 1 CPU / 2Gi | 固定模型缓存，平台开销 |
| 向量 PostgreSQL | 100m / 256Mi | 500m / 1Gi | 4Gi 初始卷，按项目记录逻辑用量 |

单副本、仅 ClusterIP，不增加公网入口。读取权限和写权限分开，凭据放集群 Secret。仅允许授权的调用链访问。通过 ops/ArgoCD 部署，启动探针覆盖模型加载，失败不能标为已就绪。单节点不是高可用方案；本地持久化也不替代独立备份。

## 接线顺序

1. 固定兼容镜像/模型，在隔离合成数据中验证中文嵌入、导入和检索契约，再部署依赖。先保持用户入口关闭。
2. 控制面维护项目知识修订与导入意图。由 LibreChat 服务端取得已认证身份，不能让浏览器自行选择其他用户或任意集合。
3. 原始文件显式导入到项目；不扫描整个个人空间，不把聊天历史自动当知识。初始每次最多 10 个 MD/TXT、每个最多 1 MiB，限制做成部署配置。
4. 先预留容量、写入导入意图，再执行有界解析/嵌入。原始文件及项目索引占用均计量，重复导入/重试不重复预留；失败释放未使用预留，保留可解释状态。
5. 检索由服务端按 owner/project/knowledge revision 限定集合；引用只显示有权读取的片段。文件提示注入不能授予工具权限。
6. 界面显示上传、索引、就绪、失败及明确重试；只有实际查询通过才可试用知识。旧版本引用的索引不随草稿覆盖或失败清理。

仅配置全局 `RAG_API_URL` 会打开原生文件检索路径，不能绕过上述授权和逻辑容量。须先核查原生路由/签名与上传归属，完成受控适配后才开放。

## 验收

使用仓库固定虚构资料：有依据的换货期限、未提供的维修价格、受限备注、注入样本、知识 v1/v2。分别验证引用支持答案、无依据说明、跨身份/项目拒绝、更新不污染旧索引、失败可恢复和重复请求不重复计量。权限不能依赖模型自觉拒绝。

记录模型修订、索引摘要、请求受理与首段回答耗时、实际资源/逻辑空间和人工干预；单次能问答不等于 P1 完成。发布固定版本与受邀者费用归属继续属于 P1-03/04 的接线门槛。
