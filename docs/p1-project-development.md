# 项目对话按需开发与工作台改造

日期：2026-11-09。状态：已实现并部署；单账号实际项目创建、修改、测试和交互预览通过。性能门禁仍未完成，不据此宣称商业可用。

## 产品约定

- 用户在项目对话描述任务。对话模型按需请求 OpenHands 开发能力，普通问答不启动执行环境。OpenHands 不再作为新会话的模型选项或已发布业务助手；已有编程会话继续兼容。
- 开发任务始终绑定经服务端核验的本人项目和根目录。受邀业务助手不能取得创建者的开发权限。聊天模型和开发模型分别选择。
- 设置按账号保存个人默认值，项目可覆盖。运行时固定本次生效配置；后续修改不影响已运行任务。策略、审批、MCP 凭据和套餐限制沿用现有校验，不共用用户配置或凭据。
- 中央聊天承接要求、进度、审批和真实结果。任务引用持久保存，刷新只恢复观察，不能重新发起相同任务。修改后下一轮能读取前次结果。
- 右侧是项目工作台：智能体上方固定高度的总览／知识库／智能体配置，下方独立对话；代码项目为预览／文件／运行。开发设置从齿轮进入同一面板，不叠加设置弹窗。
- 发布仍需原有版本、授权和验收规则，不能因为调用开发工具而自动发布。失败、取消保留文件；删除遵循已有项目清理规则。

## 配置与边界

个人默认配置只属于当前认证账号，项目覆盖同时校验账号和项目。任务使用根目录或其子目录，不能选择其他项目目录。模型只能来自管理员允许的目录；MCP 使用当前用户已授权凭据。自动调用表示系统选择开发能力，不等于跳过高风险操作审批。试用或正式业务助手不能调用开发入口。

首批沿用现有执行策略和套餐时限，不新增无执行约束的配置项。限额来源与实际生效值应可见。新默认配置须兼容已有 agent-worker；变更持久化格式时必须先核对全部消费者。

## 使用入口

1. 从左侧进入本人项目，继续使用普通聊天模型，说出需要编写、修改或测试的内容。纯讨论不会强制创建任务。
2. 模型请求开发能力后，聊天出现开发任务进度，文件和测试沿用已有执行记录。默认审批规则仍生效，自动选择能力不等于自动批准全部操作。
3. 项目「⋯ → 编程设置」或工作台顶部齿轮打开设置。选择「当前项目」覆盖开发模型、目录、策略、审批和 MCP；选择「个人默认」设置本人默认值。目录只能在所属项目根目录内选择。
4. 代码工作台使用「预览／文件／运行」。打开预览可直接操作网页；修改完成后点击刷新。文件页查看生成内容，运行页查看现有部署；本轮没有自动发布或新增通用后端预览引擎。
5. 智能体工作台保持上部固定高度，下方独立试用会话。开发设置暂时覆盖面板内容，返回后恢复试用，不将试用输入发送到中央开发对话。
