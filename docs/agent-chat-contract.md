# 编程任务在聊天中持续更新

2026-11-05。本次把审批和观察入口移入原助手回复，不改变 Kata 命令执行和审批权限。

- 创建任务后，兼容 OpenAI 的 SSE 返回一条 `[编程任务](#starbridge-task-<uuid>)` 引用并正常结束。LibreChat 将引用作为原助手消息保存，前端将完整匹配的引用渲染成任务卡片，不追加另一条助手消息。
- 新增所有者限定的 `GET /internal/v1/workspace/agent/tasks/{id}`，经 LibreChat 的 `GET /api/user/workspace/agent/tasks/:taskId` 身份桥接。没有写入、重新提交或 Kubernetes 变更。历史卡片不依赖最近十项任务列表。
- 活动任务每两秒观察；临时错误保留上次状态并重试。最终状态停止周期查询，刷新/回到会话重新读取。重试读取不会执行命令，审批 POST 不自动重试。
- 卡片显示当前状态、当前处理步骤、可折叠文件/终端结果、批准/拒绝/停止入口。最终回答直接展示在同一聊天回复里，失败/拒绝/取消不会冒充成功。
- 任务查询和审批始终使用登录身份。分享页面没有认证上下文，只显示私有提示，不请求或展示任务内容。第三方用户持有 UUID 仍得到 404。
- 后续普通聊天和编程请求会批量解析最多最近十六项任务引用，按当前用户读取最终结果，作为助手历史恢复；不可用记录明确标记，不推断成功。恢复内容不改变请求幂等依据。
- 使用持久引用避免跨数据库回写聊天正文的竞态；代价是原始聊天导出仍是任务引用，不是最终回答快照。旧版已经结束的纯提示消息没有可靠的一一关联，本次不猜测或改写旧消息。

验收包括：聊天内批准后状态继续更新、最终结果、连续两次审批、刷新同一任务、暂时读失败后恢复、拒绝/停止、超过列表窗口的历史读取、跨用户拒绝、后续上下文恢复且不重复创建任务。
