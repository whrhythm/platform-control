# 编程任务在聊天中持续更新

2026-11-05。本次把审批和观察入口移入原助手回复，不改变 Kata 命令执行和审批权限。

- 创建任务后，兼容 OpenAI 的 SSE 返回一条 `[编程任务](#starbridge-task-<uuid>)` 引用并正常结束。LibreChat 将引用作为原助手消息保存，前端将完整匹配的引用渲染成任务卡片，不追加另一条助手消息。
- 新增所有者限定的 `GET /internal/v1/workspace/agent/tasks/{id}`，经 LibreChat 的 `GET /api/user/workspace/agent/tasks/:taskId` 身份桥接。没有写入、重新提交或 Kubernetes 变更。历史卡片不依赖最近十项任务列表。
- 活动任务每两秒观察；临时错误保留上次状态并重试。最终状态停止周期查询，刷新/回到会话重新读取。重试读取不会执行命令，审批 POST 不自动重试。
- 启动阶段读取套餐/模型配置发生确定性的结构校验错误时，执行器将任务置为 `failed`，返回 `agent_configuration_invalid` 和 `finished` 事件，明确告知尚未执行、文件未修改。不再回滚认领并无限重试同一任务。数据库连接等临时读取异常仍由执行器重试。
- 聊天卡片区分等待接单与模型准备回复；排队超过 30 秒显示延迟提示（依据服务器事件时间，展示会受客户端时钟偏差影响）。没有文件或命令结果时不展示空的执行记录折叠框。
- 卡片显示当前状态、当前处理步骤、可折叠文件/终端结果、批准/拒绝/停止入口。最终回答直接展示在同一聊天回复里，失败/拒绝/取消不会冒充成功。
- 任务查询和审批始终使用登录身份。分享页面没有认证上下文，只显示私有提示，不请求或展示任务内容。第三方用户持有 UUID 仍得到 404。
- 后续普通聊天和编程请求会批量解析最多最近十六项任务引用，按当前用户读取最终结果，作为助手历史恢复；不可用记录明确标记，不推断成功。恢复内容不改变请求幂等依据。
- 使用持久引用避免跨数据库回写聊天正文的竞态；代价是原始聊天导出仍是任务引用，不是最终回答快照。旧版已经结束的纯提示消息没有可靠的一一关联，本次不猜测或改写旧消息。

验收包括：聊天内批准后状态继续更新、最终结果、连续两次审批、刷新同一任务、暂时读失败后恢复、拒绝/停止、超过列表窗口的历史读取、跨用户拒绝、后续上下文恢复且不重复创建任务。

## 回答增量与实时执行进度（2026-11-05）

- 执行器启用 SDK 的 `LLM(stream=True)` 和 `Conversation(token_callbacks=...)`。只取公开文本与 `finish` 工具的 `message` 字段；不输出 `reasoning_content`、其它工具参数或内部事件对象。`finish.message` 的未完成 JSON 字符串可逐步解码，保留中文与转义字符。
- 新事件 `assistant` 包含 `stream_id`、`text`；`command_progress` 包含 `stream_id`、`phase`、`output`。同一事件更新原快照，不为每个 token 新增事件。模型文本每 250 ms 至多写一次加密事件账本，单次文本最多 32768 字符；完成时强制保存最后一段。模型尝试替换时覆盖当前部分回复，避免重复拼接。
- LibreChat 新增所有者鉴权的 `GET /api/user/workspace/agent/tasks/:taskId/stream`。SSE 的 `snapshot` 事件携带完整任务投影，复用固定后端 GET 路由及认证身份；运行状态每 400 ms 观察一次，其它活动状态每 1500 ms。此接口不创建任务、不审批、不执行命令。
- SSE 单连接最多 25 秒，客户端自动续读最新快照。浏览器断开会中止该连接的后端读取，任务本身继续执行。GET 查询仍作为回退；利用 `updated_at` 防止慢查询覆盖更晚的流式内容。无需累计 SSE 增量或凭游标猜测缺失内容，因此刷新可直接恢复当前投影。
- 禁止缓存、压缩转换和代理缓冲；已验证的身份在每次读取时传递。错误不转发上游响应体；未获授权前不发送 SSE 正文。客户端只接收当前任务 ID，关闭页面、切换用户或任务结束后取消流连接。
- UI 在任务未完成时展示增长中的回复，完成后以最终回答替换，避免重复展示。失败/取消时保留已收到的部分回复并明确标注未完成，最终失败说明仍独立呈现。
- 命令获批后显示准备环境；执行期间每约两秒读取归属已核验的 Pod 日志，当前输出在聊天内默认展开且可折叠。日志展示上限 8192 字符，已知注入凭据及尾部未完整凭据被遮蔽；读取日志暂时失败保留上次输出，不重放命令。Python 命令环境启用非缓冲输出。其它程序自身缓冲仍可能影响可见日志时机。
- 原有命令退出码、审批、取消、Kata、配额、资源清理和不确定写入核验语义不变。应用发布的受理仍不代表应用健康，不能用模型文字替代集群观察结果。

本次未增加数据库字段；新增事件字段可由现有任务查询接口直接返回。需要同步发布 agent-worker 和 LibreChat，API 无需为此更换镜像。

## 聊天式活动反馈（2026-11-06）

- 移除厚重的执行卡片边框，公开回复在原助手消息中增量显示；后续操作说明不再覆盖前面的说明。使用与普通聊天相同的呼吸光标及主题文字动画，支持减少动画偏好。
- 新增 `model_progress` 快照，只记录实际收到的模型片段对应的阶段（思考、回复、生成操作）和累计公开文本/工具参数字符数，不保存或展示推理内容、工具参数。字符数不是 token、完成百分比，也不代表文件已落盘。思考阶段不统计内部推理字符数。
- 活动快照最多每秒更新一次，阶段切换立即更新；没有新片段不伪造心跳。前端按事件时间判断最新阶段（原快照的序号不会随更新增长）。持续显示耗时、最近保存文件；30 秒没有事件时说明正在等待模型或工具，保留停止入口。
- 公开文本仍以原有 250 ms 限速增量保存。最终结果沿用同一位置；取消/失败保留已有片段并标记未完成，结束后移除活动动画。刷新只恢复同一任务，不重复提交。
- 命令输出改为默认折叠，审批按钮继续直接出现在聊天里。执行记录和验收入口保留，运行期间不展示验收表单。SSE 写入后主动 flush，保持已有断线续读和轮询回退。
- 对单页、小游戏要求优先交付最小可用首版，简短说明操作，不自行安装浏览器或测试框架，不无休止追加检查；无法实测浏览器须如实说明。这个约束不能保证模型的首字速度或总耗时，仍需记录真实端到端时间。
- 数据库结构、套餐规则、审批、Kata 环境和用户文件所有权均未变更。发布执行器前确认没有正在运行的用户任务，避免升级中断执行。
