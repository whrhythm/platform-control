## 用户界面真实验收

- 编程设置中勾选 DeepWiki，展示工具、服务地址和外发数据说明，保存成功。
- 使用代码审查模式查询公开 `fastapi/fastapi` 文档结构，未调用工程文件、命令或发布工具。
- 聊天显示目的地、工具及查询参数；点击确认后，真实 MCP 返回文档，聊天给出最终中文答复。
- 任务记录恰好一次 `mcp_started` 与成功的 `mcp_result`。

## 集群边界与保留状态

初次实测发现执行器没有公网出口；采用 DeepWiki 当前解析出的三个精确 IPv4 `/32` 白名单，而非全公网出口。最终在执行器中验证批准地址 TCP 443 可达，未批准的 `1.1.1.1:443` 连接超时；结合已应用的 NetworkPolicy 判断其未开放。该单点探测不等于完整网络渗透测试。

另发现执行器的 `SSL_CERT_FILE` 只包含内部 CA。已使公网 MCP 传输独立采用公共 CA，并保持 TLS 域名及证书验证；不是跳过证书校验。集群内真实 MCP 查询通过。

验收结束时活动编程任务为 0。原有三个应用和文件服务均为 Ready，未改写项目文件、未发布新应用、未变更套餐或发放额度。

## 明确限制

当前只提供已审核的 DeepWiki 公开文档连接；任意服务器地址、用户 stdio、私有账号 OAuth、外部写入工具不在本版范围内。连接地址变化需要运维核验并更新 GitOps 白名单。

Lighthouse 已尝试，但本地上游前端准备脚本缺少可执行 `rimraf` shim，未能启动，不能声称通过性能门禁。远程镜像构建中的类型与功能测试已完成。Postman 当前 CLI 的 `status` 子命令不受支持，模拟证据以实际运行和调用次数断言为准。
