# 星桥编程设置使用手册

更新：2026-11-05。功能已接入星桥的 LibreChat 主聊天，不需要打开另一个 OpenHands 页面。

## 从文件夹开始

1. 打开左侧「我的空间」，在文件页点击「新建文件夹」。例如创建 `my-app`，再上传代码或说明文件。
2. 左上角模型菜单选择「OpenHands · 编程助手」，点击旁边的「编程设置」。
3. 进入 `my-app/`，点击「使用当前文件夹」。这里不能选整个个人盘根目录。
4. 选择编程模型、工作方式与操作审批，点击「保存设置」。未保存的配置不生效；当前正在执行的任务继续使用开始时的配置。
5. 回到原聊天提出要求，例如：「读取 README，创建监听 8080 的 Python 服务，添加并运行单元测试。先不要发布。」

聊天模型和编程模型分别记忆；模型列表由管理员允许目录决定。普通聊天不会启动编程执行器。切换模型不会授予额外权限或修改套餐。

## 三种工作方式

| 选项 | 可以做什么 |
| --- | --- |
| 编写与测试 | 读取、修改工程、执行测试，以及经确认提交应用操作 |
| 仅规划（只读） | 阅读工程并提出实施方案，不写文件、不运行命令 |
| 代码审查（只读） | 阅读代码和应用情况并提出意见，不写文件、不运行命令 |

先规划和只读审查通过工具能力限制生效，不仅是给模型一段提示词。若希望执行方案，改为「编写与测试」、保存，然后发送新的指令。

## 确认、观察与停止

默认严格确认：文件写入、创建目录、命令执行都暂停等待批准。新发起的任务直接在聊天回复中显示具体动作和「确认执行／拒绝」按钮。批准仅对本次内容有效，15 分钟后失效；拒绝会结束该任务，不执行该项操作。「编程设置 → 执行记录」保留为辅助入口。

「工程内自动执行」允许在选定工程内修改文件、运行命令。发布、启动、停止、移除应用、申请数据库，以及带数据库/对象存储凭据的命令仍需要明确确认。它不会把模型判断为“低风险”当作自动授权。

聊天中的同一条助手回复持续显示任务状态和当前步骤。「查看文件操作与命令结果」默认折叠，避免重复刷屏。完成后的最终回答直接显示在这条回复中。关闭或刷新页面后恢复观察同一任务，不会重复执行。需要取消时在回复中点击「停止任务」，平台停止后续操作并清理命令计算资源。已写入的文件保留，不做自动文件回滚；已提交的发布需要到应用列表观察或管理。

连接暂时中断时保留最后确认的状态，并显示自动重连提示，恢复后继续更新。下一轮普通聊天和编程会读取前序任务的实际结果作为上下文；这不等于恢复执行器内存或重放命令。旧版本的纯「请打开执行记录」消息没有任务引用，仍从执行记录查看。原始聊天导出保存任务引用，不是最终回答的静态快照。

## 测试和发布

可以要求：「在当前工程运行测试，通过后发布，等待我确认。」工程需要 Dockerfile，服务监听 `0.0.0.0:8080`，运行用户 UID 10001 可读取源码。依赖安装到工程 `.venv`，下载缓存放到 `.cache`，这些文件占用个人空间；发布源码快照不会包含这些缓存。

命令在独立 Kata 环境中运行，工作目录 `/project` 对应所选文件夹。每次命令是新进程：前一条命令的 `cd`、环境变量、后台进程不会延续；文件会保留。单条命令最长 180 秒，任务最长 30 分钟。当前支持有界测试和构建请求，不提供常驻交互终端。

发布确认后，到「我的空间 → 应用」查看构建、部署和访问地址。编程任务完成只代表助手完成本轮操作，不代表应用部署成功。发布失败请查看应用的错误原因；查询临时超时由原发布控制器自动重试，不应让助手反复提交发布。

## 数据和当前边界

- 停止任务、清理 Job 或重启执行器不删除个人盘。显式删除文件仍没有回收站，请自行备份。
- 执行器重启会把在途编程任务标为中断，要求检查结果后继续，不擅自重放命令。
- 当前为共享 OpenHands 编排服务加逐命令 Kata 计算，不是每用户部署完整 OpenHands。
- MCP 支持管理员添加、检查、审核发布服务，用户按对话选择，也可配置自己的专属凭据，见 [MCP 服务管理手册](mcp-service-management.md)。所有外部调用逐次确认；LLM 自动风险审批尚未开放。执行记录展示可验证的操作，不提供内部思维链。
- 当前面向内部可信用户，不能据此宣称已完成公网不可信代码托管的全部隔离和配额验收。
