# 发布与人工验收关联协议

本批关联工程目录、实际构建源码指纹、镜像摘要、发布修订和人工验收快照，不宣称源码指纹等于可恢复源码备份，也不替代业务数据验收。

- 人工验收保存非待检查结果时，由服务端获取与构建相同的有界源码包，记录 SHA-256。旧验收不自动补指纹；修改代码后必须重新检查。修改备注不重新绑定源码。
- 发起发布时，冻结同一所有者、同一工程最新有验收记录的已结束任务。冻结修订、加密正文、计数和源码指纹；后续编辑任务记录不改写已提交发布。
- 构建成功时，只读取本次 Job 所属 Pod 的 source 初始化容器成功终止消息。记录实际下载并交给构建器的源码包指纹，再关联验证过的不可变镜像摘要。证据缺失的新任务失败并沿用清理机制，不猜测指纹。
- 验收指纹与实际构建指纹相同才显示对应验收内容；不同则显示代码已变化、需要重新验收；无绑定记录则显示未关联。验收通过仍是用户确认，不等于平台自动验证业务正确。
- 应用接口增加 attempt（当前发布尝试）和 release（最近成功版本）。失败恢复旧版时，展示旧版的验收；构建中、停止和待核验时不冒充新版本已上线。旧发布显示缺少溯源信息，不回填猜测。
- 本批在现有 resources JSON 内保存带版本号的当前尝试及最近成功发布记录，不新增表，不保留无限发布历史。先部署兼容控制器，再启用 API 写入；其他消费者保留新增键。任务验收与套餐结构不变。
- 默认分享文本仅包含工程、状态、链接、版本和验收计数；人工需求及验收正文只在登录用户界面展示，不随复制交付说明自动对外分享。

边界：构建目录会排除 `.git`、`.cache`、`node_modules`、`.venv`、`__pycache__`、`.pytest_cache`，沿用现有 48 MiB 源文件和 64 MiB 传输限制。此指纹说明构建输入相同，无法保证远程依赖、外部服务或数据库状态相同。长期发布历史、不可变源码下载和自动业务验收不包含在本批。
