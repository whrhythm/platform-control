## 接线方案

- 复用 P1-03 不可变试用快照与原生 LibreChat 流式聊天。项目保存当前正式版本指针；发布必须同时核验当前草稿摘要和人工验收，重复请求只产生一个发布版本。
- 独立应用链接进入应用说明页，不展示创建者工程、指令或开发聊天。每个成员与发布版本绑定一个私人聊天入口；该入口仅保存占位配置，真正执行仍从控制面读取发布快照，原生编辑不能覆盖。
- 成员按已验证的 OpenID 身份绑定，邮箱只用于创建者查找已经注册的成员。不得以浏览器提交的 owner/sponsor 或邮箱本身授权。
- 服务端为每次真实回答签发短期调用凭据，绑定 actor、正式版本、会话与回答 ID。凭据只在 LibreChat 后端和模型网关之间传递，模型网关解密创建者原有 key 调用 LiteLLM；成员个人 key 不参与此调用。
- 应用独立预算是创建者账户内的使用上限，不是另一次充值。每步模型调用以价格目录保守预占，完成后按返回 token 和目录计量释放差额；这项计量是预算控制估算，实际扣费以 LiteLLM 账户为准。未知结果保留预占，不自动重发或擅自退款。目录价格未知时拒绝启动。
- 发布历史和成员会话保留。停用不删数据；删除仍被正式版本引用的知识必须先停用对应应用，不允许后台清理绕过引用。
- 真实 UI 使用原指定创建者与本轮获授权的两个合成测试账号；验证受邀访问、未授权拒绝、撤销、草稿隔离和付款主体。正常聊天、个人文件和现有应用不迁移。

## 本轮门槛

发布幂等与旧确认失效、跨成员/版本拒绝、敏感配置不下发浏览器、成员撤销后的知识/模型拒绝、预算并发预占、上游失败不自动重放、创建者实际消费而成员未扣费。完成构建部署与真实 UI 后再补版本、结果和遗留限制。

## 使用路径

1. 创建者进入“我的空间 → 项目”，打开对应 AI 项目的“发布与成员”。先在“配置与预览”完成当前草稿的真实回答及来源验收。
2. 设置应用累计模型预算上限（美元），确认承担成员费用，再点击“确认发布”。预算是应用在创建者模型账户内的消费限制，不是充值。
3. 将应用链接交给成员。成员先用自己的账号登录，打开链接后可看到“我的成员 ID”；将这个固定 ID 发给创建者。
4. 创建者将成员 ID 填入“成员 ID 或已验证邮箱”，点击“添加成员”。若使用邮箱查找，邮箱必须已由身份提供方验证；不将未验证邮箱或可修改显示名作为授权依据。
5. 成员从同一链接核验权限并“开始使用助手”。使用固定正式版本；创建者的草稿、文件和开发聊天不对成员开放。原生聊天会话属于成员自己。
6. 创建者可撤销成员或停用整个应用。撤销使用持久账号 ID，不依赖邮箱仍存在或未改名；后续调用及重新读取来源被拒绝。已发送给成员的回答无法从其浏览器或记忆中收回。

## 真实 UI 验收

环境：单节点内部集群；创建者为用户指定账号，另两个身份是本轮明确获准创建的受邀/未授权合成测试账号。通过实际登录、项目卡片、发布页和聊天入口操作；没有直接写数据库补发布、授权或计费状态。所有售后资料为虚构材料。模型为 `deepseek-v4-flash-v2`，并发为 1。

| 场景 | 结果与记录 |
| --- | --- |
| 第 1 轮 | 已接受的试用 5 发布正式版本 1；刷新后仍存在；成员回答正确的 14 天和来源，完整回复约 7.952 秒 |
| 第 2 轮 | 草稿修改标识后，旧版仍返回旧标识；试用 6 人工验收后发布版本 2，成员新会话返回 P104R2，约 6.784 秒 |
| 第 3 轮 | 试用 7 验收后发布版本 3，成员新会话返回 P104R3，约 8.984 秒；回访旧版 1 仍保留原标识，约 5.409 秒 |

### 创建者实际付费

首次成员回答前后，创建者 LiteLLM spend 从 1.704028800000001 增至 1.705173900000001 美元，差额 **0.0011451 美元**；对应两条实际消费 0.000318 与 0.0008271 美元。两个测试成员的 spend 均为 0，赠额仍各为 1 美元。应用预占结算为 1146 微美元，是目录估算，不能等同供应商最终账单。

初版发现当前 LiteLLM 会过滤顶层自定义 metadata；已将归属信息写入其 `spend_logs_metadata`。修复后的实际记录包含 actor、sponsor、project、release、app_call_id 与用途；旧版会话回访的两条消费分别为 0.0007827 与 0.0008994 美元，付款者为创建者，调用者为受邀成员。历史被过滤字段不伪造补写。

最终成功重试的两条消费为 0.0002973 与 0.0003261 美元，仍全部归创建者；两个测试成员最终 spend 为 0。应用台账为 13 条完成（估算 7655 微美元）及 1 条待核验（预占 3294 微美元）。创建者期间也做过私人试用，因此整个账户起止差额不能全算作成员消费；应按上述调用归属核对。

### 失败与人工介入

- 构建门禁曾发现声明导出、i18n 类型、路由参数类型和测试 Array.at 兼容问题，修复后重新构建；不把失败镜像记为已发布。
- 自动化登录曾因缓存会话/SSO 跳转时机失败，改为真实登录页入口后继续；这些属于验收脚本人工修正，不代表用户首次登录无阻塞。
- 预算不足测试正确阻止消费，但最初显示泛化英文限流提示；修复为固定错误码、中文说明与终止重试，最终回访单列记录。没有通过数据库强改预算；测试后的正常预算通过 UI 恢复。
- 最终恢复后首次请求的模型连接中断，UI 显示终止错误；150 秒正确答案断言失败，保留 3294 微美元待核验预占，LiteLLM 有 0.0001518 美元实际消费。没有自动清零、退款或假设未扣费。明确重试会话 `3e4489fe-cef7-5687-bf50-70f5a07353ee` 成功。上游通用断流错误仍有英文文案，列入 P1-05；预算提示已为中文。
- 最终复访又遇一次创建者 SSO 自动化跳转失败，未发模型请求；改为复用成员现有登录会话完成重试。只读观察曾因等待 networkidle 遇到持续轮询而超时。这些是验收脚本的介入记录，未修改产品数据库。
- 截图、运行状态及费用证据保存在原目录 `platform-control/release/p1-releases-*`（Git 忽略），包括失败记录；账号密码、浏览器登录状态与用户侧栏截图不提交仓库。
