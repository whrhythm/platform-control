# P1-04 正式发布与受邀使用

实施中，不是交付证明。用户任务：创建者将已验收的固定试用发布，邀请已注册成员；成员只使用业务助手，由创建者承担模型费用。草稿修改不影响线上，撤销访问立即约束后续模型与知识请求。

## 接线方案

- 复用 P1-03 不可变试用快照与原生 LibreChat 流式聊天。项目保存当前正式版本指针；发布必须同时核验当前草稿摘要和人工验收，重复请求只产生一个发布版本。
- 独立应用链接进入应用说明页，不展示创建者工程、指令或开发聊天。每个成员与发布版本绑定一个私人聊天入口；该入口仅保存占位配置，真正执行仍从控制面读取发布快照，原生编辑不能覆盖。
- 成员按已验证的 OpenID 身份绑定，邮箱只用于创建者查找已经注册的成员。不得以浏览器提交的 owner/sponsor 或邮箱本身授权。
- 服务端为每次真实回答签发短期调用凭据，绑定 actor、正式版本、会话与回答 ID。凭据只在 LibreChat 后端和模型网关之间传递，模型网关解密创建者原有 key 调用 LiteLLM；成员个人 key 不参与此调用。
- 应用独立预算是创建者账户内的使用上限，不是另一次充值。每步模型调用以价格目录保守预占，完成后按返回 token 和目录计量释放差额；这项计量是预算控制估算，实际扣费以 LiteLLM 账户为准。未知结果保留预占，不自动重发或擅自退款。目录价格未知时拒绝启动。
- 发布历史和成员会话保留。停用不删数据；删除仍被正式版本引用的知识必须先停用对应应用，不允许后台清理绕过引用。
- 真实 UI 使用原指定创建者与本轮获授权的两个合成测试账号；验证受邀访问、未授权拒绝、撤销、草稿隔离和付款主体。正常聊天、个人文件和现有应用不迁移。

## 本轮门槛

发布幂等与旧确认失效、跨成员/版本拒绝、敏感配置不下发浏览器、成员撤销后的知识/模型拒绝、预算并发预占、上游失败不自动重放、创建者实际消费而成员未扣费。完成构建部署与真实 UI 后再补版本、结果和遗留限制。
