# 聊天内编程任务验收

日期：2026-11-05。使用指定现有普通账号，从 LibreChat 页面发起与批准，没有通过脚本直接提交编程任务。

已通过的真实流程：

1. 在编程设置选择原验收工程，采用逐次确认；从聊天发送创建独立测试文件和运行计算命令的要求。
2. 原助手回复显示任务卡片；刷新后仍是相同 task ID；直接在卡片中完成两次审批。
3. 第二项审批后，聊天显示正在运行命令；用浏览器网络拦截模拟两次查询 503，保留执行中状态并出现重连提示，恢复后自动显示最终回答。
4. 命令实际输出 `1111111110`；同一回复同时提供可折叠文件操作、终端结果和最终回答，未打开执行记录窗口。
5. 完成后刷新，仍只有一个任务回复。只读核对日志恰有两次决定、一个终端事件，未重新运行。
6. 切换普通聊天，询问上一项任务输出，助手回答实际数字，没有创建另一个编程任务。
7. 另发起一项待批准写入，在聊天中停止，显示「已停止」及最终说明；没有文件写入事件。
8. 亮色和暗色均复核。没有修改原三个业务应用、删除用户文件或新增充值。

自动检查：控制面全量 207 passed / 27 skipped；补充上下文转发及最终状态竞态后，工作台定向检查 19 passed / 1 skipped。前端新增三项交互检查通过，覆盖审批到最终回答、重新挂载、断线保留状态及匿名视图不读取私有任务；身份桥接三项检查通过。镜像内各工作区类型检查及既有 94 项界面回归通过。

最终状态保护覆盖：取消/中断/完成已确认后，迟到的执行器返回不会覆盖状态或追加第二条最终事件。部署执行器前只读确认活动任务数为 0。

接口和恢复约定见[聊天任务协议](agent-chat-contract.md)，操作见[编程设置手册](agent-workbench-guide.md)。原始截图、任务编号、浏览器状态留在忽略的 release 目录，不提交个人提示词或会话凭据。

限制：旧版已结束的纯提示消息不自动关联；原始聊天导出仍包含持久任务引用，而非最终结果快照。Lighthouse 已尝试，但本机 npm 缺少 rimraf 可执行入口，未获得性能评分。Postman CLI 1.74.0 不支持技能所述 `postman status`，未将该检查报告为通过；本次故障恢复证据来自新增单元测试及真实浏览器的明确 503 注入，不声称运行了新的 Postman 模拟环境。
