# P1 全局资源与能力导航改造

2026-11-08。用户已授权按讨论草图分阶段实施，先更新纲领和清单。保留原生项目、会话、文件、发布、授权和费用记录；不通过迁移/清空数据来制造整洁界面。

## 目标与职责

- 对话与项目：普通问答与长期创建工作，原生 Projects 是唯一项目载体。
- 智能体：系统提供、公共、我发布的、分享给我的可用助手；草稿在项目/构建器中管理。公共使用、编辑权、源码/知识读取权分别授权。
- Skills：保留全局公共、个人、定向共享目录；项目按版本引用，不复制目录。公开使用不授予依赖工具权限。
- 资料空间：用户唯一逻辑空间的全局入口；工作文件、知识库、镜像、对象文件、数据库按资产管理，不另建空间。一个用户可有多个知识库，助手与库按明确授权关联。
- 部署应用：代码服务的发布状态、地址、版本、日志、资源和生命周期，不与智能体列表重复建设。
- 底部用量：双环分别表示存储与模型金额额度使用率，实际 tokens 单列；未知/过期读数不伪装为零。通知必须来自真实事件并有状态，不伪造未读数。

浏览入口只改变左侧，不改变中央会话、未发送内容和正在执行的任务。编辑/分享/管理由明确操作打开工作窗口。移动端通过既有导航选择器使用相同入口。

## 现状核查

- 可复用：原生项目与侧栏、原生 Skills 权限入口、个人工作文件操作、应用状态/管理、CapacityAccount 实际用量与套餐、项目知识修订、固定助手试用/发布和受邀访问。
- 当前知识实现仍是项目绑定的修订式导入，不是独立多库及文件级编辑自动索引。A 批次不将“项目知识”标成通用知识库，不展示不存在的镜像/数据库浏览按钮。
- 原生智能体构建器不等同已发布助手目录；A 不仅改名就声称已完成目录分离。
- 公共 Skill/智能体的审核、发布版本、授权兼容及费用策略须在 C/D 核查；不得把原生可分享对象直接认定为平台已审核公共成果。
- 现有存储账本可显示组件读数，但不等于镜像、所有临时盘、共享基础层与备份已完整归属。必须保留完整性/更新时间提示。

## 知识与分享的后续契约

知识库是资料资产，知识检索是工具，业务助手是使用能力的发布成果。选择知识检索后选择/新建知识库，再上传资料；支持空库，待资料就绪后才能声称可检索。编辑支持格式明确，PDF/Word 第一版优先预览/替换，不把提取文本改动当作修改原文件。保存形成新原文修订，自动索引，旧任务不覆盖新结果；正式发布的助手仍固定已确认知识版本。删除先查引用并撤销相应访问，不能只删列表。

成员额度为创建者预算内上限而非转账；已用和在途预占不因撤销/修改上限清零。未知费用继续核验。首发公共访问限定登录用户，匿名访问不随 UI 开放。邀请对象核验、接受、取消/撤销、到期和费用承担必须可见；错误提示不泄露账号敏感状态。公开使用不公开工具凭据、开发目录、私人记忆或所有知识原文。
