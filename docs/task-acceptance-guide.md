# 聊天中的本轮需求与验收

更新：2026-11-06。产品优化第二批：把一次编程任务的原始需求、执行证据和人工验收记录放在同一个入口，刷新后仍可继续查看。

## 如何使用

1. 像平时一样，在 LibreChat 选择 OpenHands、选择工程并发送需求。每条编程任务卡片都有「本轮需求与验收」。不必离开聊天，也不要求每轮都填写表单。
2. 打开后，新任务会展示这轮用户消息作为初始目标；早期任务可自行补充。修改这里的目标只改变验收记录，不会改写已经提交的 Agent 指令。需要继续改代码时，仍在聊天里下达新指令。
3. 添加可实际检查的条件，例如「导出 CSV 后中文没有乱码」，然后保存。最多 12 项。任务执行中也可以整理条件，结束后再选择「我已确认通过」或「需要修改」。
4. 查看命令执行次数、记录到的文件写入；在原任务的执行详情里核对输出，或实际打开应用检查业务。命令成功、Agent 完成和用户验收通过是不同结论。
5. 选择结果、填写检查备注后保存。任务卡片显示通过项数和需修改项数；刷新或重新登录后可重新打开该任务查看。
6. 修改目标或验收条件会重置相关通过结果。先保存新条件，再重新检查、记录结果。后续任务不会继承本轮的通过结论。

建议先列两三项最重要的业务结果。验收清单的目的，是保留「我确认了什么、还有什么要改」，不是替用户制造更多必填步骤。

## 保存失败怎么办

- 读取失败时显示重试，不把旧记录当成空白表单。
- 保存失败时保留本窗口草稿。可以重试相同内容；如果上一请求实际已成功，不会重复生成修订和审计记录。
- 另一页面已经修改时显示冲突，防止旧页面覆盖新内容。点击「重新读取已保存记录」会先询问是否放弃未保存草稿。
- 关闭有未保存修改的窗口也会询问。草稿只在当前打开的窗口内保留，直接刷新浏览器仍会丢失尚未保存的内容。

## 记录的含义

这份验收绑定**一个编程任务和当时的工程目录**。它不能证明后续改动、某个发布版本或当前线上应用已通过验收。因此，「应用 → 交付说明」中的业务验收暂时不会自动引用此记录。

文件摘要仅来自成功记录的文件写入/创建操作，不是完整代码差异；命令可能修改其他文件。退出码为 0 只表示命令成功，不能自动称为业务测试通过。当前保存最新验收正文和每次保存的审计元数据，不提供历次正文对比。

旧任务没有独立保存的原始需求时，不会从包含系统提示和历史聊天的内部指令中猜测内容。新任务最多显示本轮需求的前 4000 字符，超出时注明截断。

## 实现与兼容

读取和保存通过 LibreChat 已登录身份关联任务，不接受浏览器传入所有者；Agent 工具不能替用户记录人工通过。正文沿用平台现有密钥加密，审计不写入需求或验收正文。

使用 AgentTask 的现有 resources 字段保存带版本号的记录，没有修改数据库结构、套餐策略或 AgentConfig。旧 agent-worker 的资源更新会保留额外键；本批只更新 platform-api 和 LibreChat 镜像，不要求更换工作器。接口及冲突处理见[协议](task-acceptance-contract.md)。
