# B 知识资产生命周期：实施契约

2026-11-08，承接 `p1-resource-navigation.md`。当前状态：设计核查完成，实施中；以下目标未部署前不得称为已可用。

## 用户任务与范围

资料空间 → 知识库 → 新建空库 → 上传 MD/TXT → 查看文件就绪/索引中/索引失败 → 预览、编辑、重命名或删除 → 自动索引 → 在项目知识中选择一个库 → 新试用引用该库的已就绪修订。一个用户可有多个库，同一库可供多个自有项目引用；首批一个助手绑定一个库，不承诺多库联合召回。PDF/Office 的解析、预览与替换不在当前已支持格式内，不开放无效上传按钮。

知识管理是显式打开的工作窗口，保留中央聊天、草稿和原生项目 ID。使用者获得助手调用权不等于读取所有原文或管理知识库。平台公共知识授权属于后续目录阶段。

## 数据与兼容

- 新增 `knowledge_libraries`：用户环境归属、名称、创建幂等键、当前编辑修订 `head_revision_id`、最新可用修订 `active_revision_id`、元数据版本及软删除状态。
- 复用 `project_knowledge` 的加密原文、索引任务、租约、逻辑容量计量；增加 `library_id`，旧 `project_id` 保留，允许新库修订没有项目。索引 scope 为旧 project_id 或新 library_id，旧向量不搬迁。
- 迁移只为已有项目资料建立默认库并关联原记录，保持每个旧修订 ID、原文密文、向量 scope、试用、发布和会话不变。不把空项目伪装成知识库。
- 项目草稿保存选中的 library_id 和已确认修订；试用与正式发布继续固定 revision_id。修改库更新草稿可用版本，绝不改写已有试用与发布快照。
- 新库修订以库范围 request_id 幂等，编辑必须带 expected_revision_id。并发旧页面保存返回 409，不能覆盖新内容；同请求重试返回原结果。

## 文件与索引

文件操作提交完整、不可变的一份库修订；首批限额沿用已有小资料限制。保存、上传、重命名、删除自动排队，文件列表显示该修订状态。只允许最新编辑修订成为 active；迟到任务、重试及已删除库不能恢复旧内容。新索引失败保留上一可用版本，界面显示当前失败与正在使用旧版，用户可重试。

删除最后一个文件形成可用的空修订，不调用嵌入服务；检索返回空结果。原文预览需经过所有者授权，不能执行上传 HTML。旧修订仍按实际存储占用计费，不把逻辑删除文件当作立即物理释放空间。

库删除先检查草稿绑定和固定试用/发布引用；有引用拒绝并说明关联对象。无引用才进入清理队列，完成索引删除后释放容量，清理失败继续保留预留并重试。历史项目导入/删除接口继续兼容，不允许绕过库引用保护。首次不自动清理任何已发布或已试用修订。

## 权限、限额与发布顺序

所有操作从认证主体解析用户环境，不相信浏览器提交 owner。库、项目、修订需同环境；修改/绑定审核权限由现有 LibreChat 创建权限与平台所有权联合执行。绑定允许空库，但界面不能声称可检索。正常已发布成员检索按固定版本及当前授权执行。

容量仍为原文与索引逻辑字节，沿用已有容量预留、环境锁顺序与失败读数保护。新增库数量上限可配置；每库文件数、单文件大小、修订数沿用现有设置。UI 显示实际限制。

升级须先备份并验证迁移；先更新所有读取新模型的控制面组件及知识 worker，再打开新 UI。旧 worker 不得处理新库修订。回退先关闭入口/停止新写入，保留新数据，不直接降级 schema。向量服务协议与嵌入模型本批不变。

## 验收

必须覆盖：空库、多库隔离、一库多项目引用；上传/预览/编辑/重命名/删除/重试；并发版本冲突、幂等、乱序索引、故障与恢复、限额；旧项目/试用/发布检索兼容；迁移前后 ID 和数据保留；真实 UI 指定账号完成资料维护及新试用，亮暗/窄屏/草稿保持。单元、隔离 HTTP、迁移、构建与真实部署分开记录。完成后追加纲领第 10 节证据。
