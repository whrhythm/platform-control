# 星桥产品纲领与阶段交付标准

版本：1.7。更新日期：2026-11-08（北京时间）；初版生效日期：2026-11-06。适用于产品设计、代码开发、测试、部署和商业试点。

本文是后续产品工作的统一基准。核心决策已由用户确认：以可交付、可持续运行的应用为交付对象，以 AI 对话驱动创建与修改。本文规定目标和验收标准，不把目标写成已上线能力。后续用户的明确决定优先；既有技术契约、数据保护与权限要求继续有效。

**当前授权：全局资源与能力导航分阶段改造。** 用户已确认 2026-11-08 草图，当前以[实施清单](p1-resource-navigation.md)为准，先交付 A 批次全局入口与真实用量，再依赖契约推进知识生命周期、可用助手/共享、私有工具与自然语言构建。已有[项目左侧详情](p1-project-inspector.md)、原生合并及权限修复保留；浏览资源不得替换中央聊天或丢失未发送内容。计划、实现、部署和真实 UI 验收分别记录。

## 1 产品承诺

实施状态（2026-11-08）：A 全局入口与真实用量、B 知识资产生命周期、C 私人/受邀可用助手与分享均已有实现、部署及指定账号 UI 功能验收记录；B 首批支持私人 MD/TXT 库，每助手绑定一库。C 提供显式接受、撤回、成员额度/有效期和只读使用权，保留旧会话与费用；公共审核目录尚未开放。性能及商业门槛仍待补，D/E 未交付。下一批聚焦 D 受控能力与自然语言构建，具体边界与证据以[实施清单](p1-resource-navigation.md)为准。

**帮助个人与小团队通过对话，创建、试用、发布并持续维护可以交给别人使用的应用。**

产品类别为 AI 驱动的应用创建、交付与维护平台。有两类主要交付对象：对话型助手，以及可以独立运行的网站、后台或 API 等代码型应用；二者可独立使用，也可在同一项目内组合。用 AI 创建应用，不意味着交付物运行时必须调用 LLM。对话型助手围绕知识、方法和授权工具完成任务；代码型应用可以具有自己的登录、用户管理、数据库和文件存储，并在平台部署、运行和维护。首发支持范围须明确，不承诺任意软件自动生成。

### 默认通过自然语言创建与修改

智能体项目的中央对话承接创建与修改。右侧工作台上方为「总览／知识库／智能体配置」三个页签，下方保持独立的试用版本和会话。总览仅呈现当前试用实际观察到的提交、模型输出、工具请求、运行时处理、结果及后续输出；收到结果本身不证明模型已经继续生成，收到错误也不计为工具成功。知识库页签在同一区域显示文件树与预览。智能体配置复用 LibreChat 的模型、指令及 Tool Library 组件，手工保存与自然语言生成写入同一份受控草稿，旧建议不得覆盖新版本。发布沿用已验收草稿、访问范围和额度校验。

首页保留普通聊天。创建者在原生 Projects 的“新建项目”选择智能体或应用、填写名称，再填写一个新的英文根文件夹名称。平台在项目创建时创建专属目录，已有目录继续归原有项目或资料空间所有。资料空间展示目录树及项目名称标签，项目改名更新标签，目录路径保留。创建成功进入项目开发对话。项目列表按类型显示图标，项目菜单打开右侧试用工作台，提供应用网页预览或独立的助手试用聊天，助手同时展示当前草稿能力与授权。用户唯一的持久个人空间以“资料空间”进入最左侧常用导航，个人菜单入口指向同一空间；管理个人资产与容量，不作为第二套项目入口。新项目在既有个人空间内建立目录，不重复创建用户空间。

采用“原生 Projects 统一入口、中央对话”：项目直接位于 LibreChat 会话侧栏的原生 Projects 下，不保留第二个星桥项目图标或列表。扩展原生项目以关联助手、编程目录、知识、版本与发布；现有项目和会话保留 ID、归属和数据，以可重试的关联方式接入，不按同名自动合并。项目按需提供创建、资料、能力、设置、试用和发布入口；长文档编辑和详细设置允许显式进入主工作视图并返回聊天，不能强行把所有内容塞进窄栏或自动覆盖聊天。

改良已有 LibreChat 智能体构建器，目标是自然语言创建/修改与高级手工设置维护同一份草稿。创建者可从输入框“＋”或空白引导选择智能体创建、编程工作；系统先多轮澄清必要信息并准备草稿，需要知识时先建立/关联知识库，随后引导添加资料，不在助手意图未明确时强制上传。知识资料、临时附件、生成文件与 Skill 附属文件分别表达；工具和技能以用途呈现，详细参数按需展开。已实现的草稿/原生 Agent 同步范围必须经契约核实，不把两个配置副本显示成已自动同步。

创建对话与业务助手试用明确区分；已有成果决定可见管理区，LLM 不能通过输出文本伪造资源创建成功。资料、连接、授权、错误和费用状态须可见。功能未接通时明确限制，不放假按钮或用普通聊天冒充自动保存助手。

普通用户描述目标，平台根据当前可用能力生成可试用草稿，并自动建立或关联项目。Prompt、模型、Skill、Tool 和 RAG 参数由系统按受控规则准备，不要求用户先学习这些术语或填写配置表。用户通过真实任务试用，再用自然语言提出修改；高级配置保留给需要精确控制的用户，不是默认起点。

“一键生成”指生成可验证的草稿，不等于自动授予权限、完成外部系统接入或直接发布。只追问缺少的必要资料、业务规则、授权和费用确认。系统必须区分“已准备好”“需要资料/授权”“当前不支持”，不能编造不存在的工具或把待接入能力展示成可执行。每次修改形成草稿和简明改动摘要，正式版本保持不变，试用确认后再发布。

自然语言创建依赖管理员维护并发布的能力目录，详见第 4 节。目录不能只存在于一段人工维护的系统提示词中；创建助手的 LLM 应收到与当前用户、项目和环境匹配的结构化能力信息，生成结果须由服务端核验。

能力获取有三条路径：复用已审核工具、按授权连接外部工具、由开发助手按需开发项目私有工具。第三条路径使编程能力服务于对话助手的创建，但不允许线上业务助手修改自身代码、授予自身权限或绕过发布流程。完整关系、审批分工及联合发布见[总体设计](overall-design.md)。

用户购买的是任务完成质量、交付效率和持续使用的确定性。模型、Agent、文件空间和运行资源是实现这一价值的支撑，不是需要用户自己拼装的产品。

完整生命周期固定为：**创建 → 试用 → 修改 → 发布 → 持续维护**。任何阶段的设计都必须回答：用户要完成什么、当前发生了什么、结果在哪里、下一步能做什么、需要承担什么费用。

产品不以按钮数量、接入组件数量、代码量、模型自称完成或一次演示成功衡量进展。

核心痛点是：用户知道业务目标，却需要自行拼接模型、资料、工具、权限、运行环境与费用才能交付。星桥应降低这项交付和维护成本。首次获得正确结果、别人能独立使用、后续修改可控，比可配置项的数量更重要。

## 2 服务谁以及先解决什么

| 角色 | 核心需求 | 默认能力边界 |
| --- | --- | --- |
| 应用创建者 | 熟悉业务但不愿承担完整开发与运维，通过对话完成一个实用 AI 应用 | 管理自己的项目、知识、工具授权、版本、访问范围与预算 |
| 应用使用者 | 使用已发布助手或业务系统完成任务 | 使用被授权的应用，不默认看到源码、开发聊天、系统指令或密钥 |
| 团队购买者 | 确认业务价值、持续费用、成员访问和数据可控 | 了解账单与权益，不因付款自动获得跨团队权限 |
| 平台管理员 | 处理用户、套餐、模型、能力目录审核、异常与运营 | 在 Platform Control 管理 Tool、Skill、RAG 等能力的登记、验证、发布与停用；敏感操作有依据、权限和审计 |

### 目标客户与购买者

第一优先客户是假设有重复知识问答、资料处理或简单业务操作需求的小团队；主要创建者为业务负责人、运营负责人及内部工具负责人，团队或创建者承担费用。第二优先是向客户交付 AI 助手的顾问、实施人员和小型服务团队。技术开发者是进阶用户，不要求普通创建者先理解容器、模型代理或存储卷。

这两类客户是假设，不是已验证市场。先选择一个相近任务群做访谈和受控试用，分别验证节省的时间、交付周期、支持负担和付费意愿；不同时承接多个行业定制。应用使用者通常只需要完成任务，不应被迫购买创建套餐或配置模型。

同一个账号可以是自己项目的创建者、别人应用的使用者；角色必须按资源判断，不能用一个全局“普通用户/管理员”开关代替业务权限。

### 行业中立与样板边界

首发验收样板保留**售后 AI 助手**：依据获授权的资料回答问题，必要时创建或查询工单，说明实际处理结果。它覆盖知识、权限、写操作、持久数据和维护，便于形成可重复测试；已有工单网页不等于这个闭环已完成。

售后是测试样板和获客场景假设，不是平台的行业定位。工单、售后字段和数据库不得成为所有项目的必填项。内部制度、项目资料、资料审查等相邻助手应复用同一产品结构；这些例子不自动扩大首发支持范围。验收模板必须与默认创建流程分开，业务规则不得写死进通用模型、权限和发布逻辑。

首发不承接关键交易、强监管敏感数据、复杂企业定制或未经验证的全天候服务承诺。正式接收真实客户数据之前须通过数据保护门槛。

## 3 产品边界与扩展规则

### 应当做

- 以自然语言创建和修改对话型助手，按需组合知识、Skill 与授权工具；保留高级配置及真实结果反馈。
- 通过编程助手创建和修改独立代码应用，支持明确范围内的网站、API、登录、业务用户、文件和持久数据；也可作为对话助手的配套能力。
- 应用的测试、版本发布、访问控制、用量、反馈、运行维护与退出导出。
- 普通用户可直接完成主要任务；模型、system prompt、工具、Skill、检索参数等在合适的进阶入口可配置。

### 近期不做

- 万能低代码搭建器、通用商城/ERP 工厂、游戏开发平台，以及与主场景无关的写作和音乐入口。
- 同时接入多个工作流引擎、公共模板/组件交易市场、自动选模型优化、复杂分支合并或大规模企业定制。
- 为展示某项组件能力而增加独立产品入口，或要求用户先理解全部底层术语。

HTML、小游戏和纯网页可以作为回归测试样本，不能成为产品定位或整体验收的替代品。也不承诺任意语言、框架、数据库或工程都能即时预览和部署。

引入 Langflow、Dify 等组件前，先记录当前用户任务的具体缺口、既有能力为何不能满足、接入成本、权限与计费影响、退出方案及可测验收条件。只有确实缩短主流程或改善质量时才进入排期；组件选择不是产品阶段。

### OpenHands 与部署的适用范围

OpenHands 是可替换的开发助手，可开发独立代码应用，也可补齐自定义工具、接口或页面。代码应用的创建、交互预览、修改、部署和持续维护是完整主路径，不能仅作为聊天助手的附加按钮。没有代码需求的用户，应能绕过编程、构建镜像和服务部署完成助手交付。不能将 OpenHands 的安装或执行环境当作产品价值本身，也不把开发权限传给应用使用者。

“发布助手”是确认版本、访问范围与费用；“部署服务”是运行自定义程序。前者不要求每次创建容器、数据库或独立域名，后者按实际需要启用。配套代码涉及发布时，仍须绑定其版本和验收记录，不能成为权限、配额或数据保护的旁路。

代码应用的运行入口应提供访问地址、当前版本、运行状态、日志、CPU/内存、文件与数据库用量，以及受配额约束的规格调整、重启、暂停和恢复。备份、导出和销毁须说明范围；暂停或发布失败不删除持久数据。代码版本回退不等于业务数据库回退，涉及数据迁移时必须说明影响并保留恢复路径。以上为产品要求，各项实际支持范围仍需独立验收。

竞争力假设在于把创建、试用、授权交付、费用和维护连成清楚可靠的体验。固定版本、知识检索、AI 编程、部署等单项能力不得宣传为独有；没有对照证据和客户价值验证，不宣称形成技术壁垒或“别的平台做不到”。

### 全局目录与项目引用

2026-11-09 导航增量：统一使用“智能体”称呼，不新增“专家模板”产品对象。知识库提供与智能体构建器同级的左侧入口，可不选择项目而创建和维护；项目工作台只引用现有知识库。资料空间的知识入口指向同一目录，不维护第二套列表或副本。本批不迁移既有归属、不修改删除策略及授权。底层知识检索和向量数据库由平台共用，数据按库与修订隔离、由控制面核验访问。管理员可选择本地 FastEmbed 或经连接检查的外部 Embedding 作为推荐模型。库所有者显式确认后重建索引，正式发布及固定试用继续使用原修订对应的模型。

全局保留可使用的系统/公共/个人已发布/定向共享智能体，以及公共/个人/共享 Skills。项目是创建和维护载体，只引用明确版本和授权范围，不将公共能力搬成项目私有副本。已发布不等于公开，使用权不等于编辑、源码、知识库管理或凭据读取权。系统编程助手独立于业务成果，用户可配置获准选项但不能删除平台内置对象。

资料空间只有一个，其中可以有多个独立知识库。知识库是资料资产，知识检索是工具，知识型助手是使用该工具的成果。一个助手可选择多个库，多助手可引用同一库；文件原文和同一索引不因引用重复计量。具体多库关联仍须契约、实现和验收，不因文档允许就认定已支持。

知识 UI 以文件列表和就绪/索引中/索引失败为核心，提供支持格式的预览、编辑或替换、重命名、删除及失败重试；内容修改自动生成新索引修订。并发更新不能被旧任务覆盖，正式助手不未经确认切换知识修订。删除考虑引用、访问撤销和索引清理。

全局导航依次服务对话与项目、可用智能体、Skills、资料空间、部署应用；用量与通知靠近底部。底部双环分别表达逻辑磁盘和模型金额额度，tokens 展示实际消耗而非虚构总额。运行 CPU/内存与磁盘计量分开；用量区分已用、预留、缺失/过期测量。共享层和系统基础镜像不能直接计入用户总量。

## 4 核心概念不能混淆

| 概念 | 产品含义 |
| --- | --- |
| 项目 | 一个持续业务目标，关联创建/开发对话、文件、配置、可选知识、试用、发布和运行记录；承载主要应用及必要关联服务 |
| 文件资产 | 用户上传或生成的原始资料、代码、图片和结果文件；有来源、所有者、用途、保留与引用关系 |
| 应用 | 用户实际使用的对话助手或独立代码应用，也可为两者组合；可以私人试用，发布后按明确范围交付，不等于容器或镜像 |
| 开发助手 | 帮创建者实现需求的 Agent，现有 OpenHands 属于此角色；默认不向最终应用使用者开放 |
| 业务 Agent | 已交付应用中的任务执行者，依据发布版本的行为、知识和授权工具工作 |
| Skill | 可复用、有版本的任务指导或操作方法；绑定 Skill 本身不能授予工具、文件或外部系统权限 |
| 工具 | 具有明确输入、输出、权限和副作用的能力；MCP 是接入方式之一，不等于自动可信 |
| 知识库 | 经授权导入、索引、检索和更新的资料；与普通工程文件区分，权限需贯穿检索与回答 |
| 草稿 | 创建者正在修改的代码与 AI 行为配置，不自动影响线上版本 |
| 试用环境 | 对指定草稿进行对话或页面验证的环境，明确数据和工具操作范围 |
| 发布版本 | 已确认的代码/镜像、Agent 指令、模型配置、Skill、知识索引版本与工具权限配置的可追溯组合 |
| 应用使用会话 | 最终用户与已发布应用的对话，不能混入创建者开发聊天或其他用户会话 |

发布记录保存凭据引用和授权范围，不复制明文密钥。模型名称或别名不保证供应商行为永久不变；应记录实际调用模型与路由变化，并在变更后回归验证，不宣称外部模型完全可重现。

用户个人空间是持久资产的载体，项目归属和隔离由服务端保证。它不等于某个容器、某一份 PVC 或一次聊天。一个用户可以有多个项目；普通聊天不必创建项目。已发布应用的最终用户不能默认继承创建者的开发环境权限。

星桥账号负责项目所有权、开发管理、资源和费用；代码应用内部账号负责该业务系统的客户、员工及管理员角色。二者不默认互通；应用访客不自动获得星桥账号、模型额度或开发权限。统一登录是可选接入，必须明确身份映射和授权范围。项目、知识与 OpenHands 不作为三个平级主流程：项目是长期载体，知识是按授权选用的资料能力，OpenHands 是按需要调用的开发助手。

### 关系与可选性

| 对象 | 是否必须由用户配置 | 关联原则 |
| --- | --- | --- |
| 项目 | 持续维护的应用需要项目记录，可随自然语言创建自动建立；普通聊天不要求创建 | 项目组织资产和版本，不能强迫用户先填写管理表单 |
| 文件 | 可选 | 上传不自动加入知识，不自动授权所有项目或成员 |
| 知识库 | 可选 | 明确选择资料后建立可检索修订；来源文件和知识修订有可追溯关联 |
| Skill / 工具 | 可选 | 方法指导和执行权限分别配置；不因绑定技能自动取得资源权限 |
| 发布版本 | 正式交付时必须；私人探索可以停留在草稿/试用 | 固定行为、选用知识和工具，以及实际需要的配套代码版本 |
| 服务部署 / 数据库 | 按任务需要 | 纯对话或知识助手不必自行部署服务；不能为套用样板额外创建资源 |

文案检查可只使用指令/Skill，制度问答可使用知识，报表处理可使用文件和计算工具，业务查询可使用授权接口。它们用于检验可选性，不要求本轮同时实现四套业务模板。UI 不得把“项目 → 上传 → 知识库 → 编程 → 部署”画成所有用户必须完成的流水线。

### 文件与知识资产的一致表达

当前 LibreChat 的聊天文件记录与个人持久工作目录是不同资产来源，不假定已经同步。“我的空间”应成为统一的资产入口；旧“我的文件”应明确为“聊天附件与生成文件”或成为同一入口的筛选视图，避免同名异义。原生聊天 Projects 是会话整理能力，不默认等于星桥交付项目；保留历史会话并解释关联，不批量隐式迁移。

用户必须能知道文件来自哪里、归哪个项目、被哪些知识修订或正式版本引用、是否计入容量，以及删除的影响。提供明确的保存到项目、选作知识、预览、编辑、下载和受控删除；文件类型不支持某项操作时说明原因。头像等系统记录不默认混入业务资料列表。

统一界面先统一资产身份和关联，不先强行搬动底层存储。引用同一资产不因重复入口重复计费；真实副本和索引派生数据按已公布口径计量。删除附件、聊天、项目文件、知识修订和正式数据分别授权，检查引用，不得连带误删。已有文件、对话和用量迁移须有兼容与回退方案。

### 知识权限与组件演进

知识默认按所有者及项目管理，查询再限定到获授权的修订。受邀应用使用权不等于浏览整个知识库或个人空间；引用与原文读取也须授权。共享基础设施可以承载多个用户，但不能以共享数据库为由合并权限；团队共享能力须单独定义，不默认为已实现。

FastEmbed 等嵌入组件是可替换的内部依赖，不是用户必学概念。升级组件须验证检索兼容性；更换模型、分块规则或向量空间须建立新索引、验证效果并受控切换，旧发布版本继续解析正确的模型/索引。维度相同不代表向量兼容。保留源资料、修订、模型与索引版本及回退路径；升级便利性必须由迁移演练证明，不能称为已具备一键升级。

### Skill 的导入、授权与发布

公开仓库的 Skill 可以作为候选资产，不等于可直接执行或许可无限制。区分纯指令、参考资料/模板、可执行脚本及外部工具依赖；核对格式、许可证、来源版本、依赖和工具名称。导入成功与执行成功分别验收，不承诺任意 GitHub Skill 跨客户端无修改兼容。

目标流程为：导入或同步候选版本 → 兼容性与权限检查 → 私人试用 → 明确绑定项目 → 随确认版本发布。普通聊天与正式应用的能力边界分别生效；安装到原生 LibreChat 不等于自动绑定星桥正式助手。外部更新先形成待审核草稿，不能悄悄改变线上版本。

`allowed-tools` 等声明只是所需能力的输入，不能越过平台审核、创建者授权、使用者范围和运行配额。脚本、MCP、网络、密钥、文件与部署权限须逐项受控；无法提供的能力应明确阻止或标记不兼容，不虚构执行结果。不因实现 Skill 导入顺带建设公共交易市场。

### 管理员能力目录与 LLM 创建助手

**Platform Control 必须提供管理员维护的能力目录，作为自然语言创建助手的可用能力依据。** 不让 LLM 只凭通用知识猜测平台安装了什么，也不把服务器地址、凭据或所有用户的知识内容一次性塞进提示词。既有 MCP 管理等能力可复用，但完整目录、创建接线与下列门槛尚未验收，不能宣称已具备。

| 能力类型 | 管理员配置与验证 | 创建助手的 LLM 可以获知 |
| --- | --- | --- |
| Tool / MCP | 工具来源、版本、输入输出、连接方式、鉴权方案、读写副作用、执行限制、适用范围与健康检查 | 稳定标识、能完成什么任务、参数定义、前置条件、所需授权、风险与当前可用状态；不含实际密钥 |
| Skill | 来源与许可、内容版本、适用任务、依赖工具、兼容性与是否带可执行脚本 | 已审核的方法说明和适用指导、版本、依赖与权限需求；不能因选中 Skill 自动获得执行权限 |
| RAG / 知识检索 | 支持的资料格式、导入/索引/检索/引用能力、默认策略、容量限制、模型与索引兼容规则 | 当前真正支持的检索能力，以及用户获准选择的知识集合/修订与就绪状态；不含其他用户的资料或全库内容 |
| 模型与开发/运行能力 | 可用模型及适配能力、编程与预览支持范围、部署方式、资源规格和费用规则 | 当前可选且兼容的能力与限制；缺少部署或工具执行能力时不能承诺完成 |

每条能力至少有稳定 ID、版本、中文名称、业务用途、适用场景、输入输出或使用约定、依赖、权限要求、可见范围、套餐/配额限制、费用说明，以及审核和运行状态。文案面向用户；执行引用使用 ID 和版本，不能靠同名猜测绑定。费用不确定时标明计费口径与预算限制，不虚构精确报价。

管理员流程：登记候选 → 检查连接与兼容性 → 审核风险、权限及适用范围 → 发布到可用目录 → 监测、更新或停用。发现工具名称或接口不代表已审核可用；手工配置和自动发现都要经过发布流程。配置变更、审核、停用和恢复留审计记录。

自然语言创建流程：

1. 用户描述目标。创建过程的 LLM 获取按当前身份、项目授权、套餐、环境和健康状态筛选的目录；目录较大时按任务检索候选，不默认注入全量描述。
2. LLM 生成助手草稿，引用明确的能力 ID/版本，提出所需资料与授权；默认优先组合现有受控能力，不要求用户手填 Prompt、Tool 或 Skill。
3. 服务端检查引用真实存在、已发布、依赖兼容、用户有权使用、费用与配额可承担；不能以模型输出代替校验。不满足的项显示“待授权”“待资料”“暂不可用”或“不支持”，禁止静默替换成更高权限能力。
4. 用户只补齐必要资料、连接授权和有副作用的操作确认。允许先试用不依赖缺失能力的部分，但明确哪些尚未接通，不模拟成成功。
5. 试用实际调用已授权能力并展示结果与来源；确认后发布版本，保存所选能力及知识修订的可追溯引用。模型提出缺少新工具时，进入接入/审核或代码开发草稿，不能自行登记成正式可信工具。

区分“管理员允许平台提供”“创建者授权本项目使用”“最终使用者本次可执行”。三者不能相互替代。管理员配置 RAG 服务，不自动取得或公开所有用户知识；管理员登记连接器，不等于替用户授权业务账号。凭据按连接和所有者隔离、在服务端解析，不传给创建 LLM、前端或发布快照。目录发现权限不等于执行权限；运行时再次核验授权、费用和配额。

能力描述、知识文档和导入 Skill 都不能覆盖平台权限规则。发布后的正常升级先形成候选版本，经兼容性与试用验证再切换，不悄悄改变旧助手；撤销权限或紧急停用必须约束旧版本的后续调用，并明确提示受影响能力。目录或服务暂时不可用时保留草稿和已确认状态，不能把未知结果描述成“未安装”或自动重复有副作用的操作。

### 按需自动开发工具

现有目录不能满足已确认任务时，系统先说明缺少什么能力、为什么需要开发、预计使用哪些资源以及已知费用边界。在用户已授权的开发范围内，可以自动生成并测试工具草稿；新增数据访问、外部连接、业务写入或范围明显扩张时必须重新确认。无法在支持范围内实现时明确停止，不把假工具、模拟返回或生成代码当作接入成功。

默认路径：需求与能力缺口 → 工具开发草稿 → 受限环境中的代码与契约测试 → 平台准入审核及用户授权 → 绑定助手草稿 → 联合试用 → 确认并发布版本组合。自动修复有时间、次数和费用限制；中断保留源码与任务身份，有副作用的执行结果不明时先核验，不自动重放。

生成工具默认是项目私有资产，有所有者、稳定标识、不可变版本、源码/构建产物摘要、输入输出约定、依赖、权限与网络声明、测试证据、审批记录和计量归属。开发与运行环境不能继承平台管理员、集群管理或开发助手的全量权限；凭据由受控执行路径解析，不写入源码、镜像、提示词或发布快照。开发助手与工具运行身份分开。

**管理员审核、用户授权与逐次执行确认是不同的控制。** 管理员负责准入规则和工具版本审核，不能代替数据所有者授权；用户授权不能绕过平台规则；LLM 的风险判断、工具自报“只读”或模型自评测试通过都不构成授权。最终调用仍按当前调用者、应用版本、资源范围及预算校验，不能直接继承创建者的全部权限。

- 项目私有、无外网、无凭据、无持久写入的纯计算工具，仅在管理员已发布的受限运行策略覆盖且确定性检查通过时，允许规则审核通过；必须记录策略版本与证据。自动判定不明确时转人工，不默认放行。
- 新的外部连接、敏感数据访问、数据库访问或业务写入工具，首批要求管理员人工审核准确版本，用户另行授权指定数据/账号/操作范围。人工只读审核不替代参数与数据范围的运行校验。
- 外部业务写入首批仍须逐次确认具体操作；将来的限域批量授权须单独设计验收。审批不能使用一句“允许所有操作”覆盖任意后续输入。
- 申请跨用户、平台凭据或任意集群管理的生成工具不进入普通工具放行路径；管理员审核也不能越过既有隔离规则。
- 向平台目录共享需单独申请、审核来源许可与内容、取得分享授权；不因私人试用通过自动公开源码、连接或用户数据。

工具代码、构建依赖、输入输出、目标地址或权限范围改变时，形成新版本并重新执行对应准入、授权和联合试用；旧批准不能套用到新产物。凭据轮换不授予更多范围，发生主体/范围变化或撤销时重新核验授权。

### 工具与助手联合发布

“一起发布”指一次明确的用户发布意图，固定并验收助手配置、知识修订、Skill 版本、工具版本及运行产物的组合，不是将所有能力打包到一个进程，也不是宣称跨服务事务天然原子。发布快照只保存凭据引用及授权约束，运行时读取有效授权。

发布前必须确认：实际构建产物与已审核摘要一致、工具版本未停用、依赖和授权有效、联合试用对应当前全部版本、预算与运行条件满足。代码或权限声明改变后，旧联合验收不再适用于新组合。只有组合全部准备就绪才切换线上版本；局部失败保留旧组合，首次发布失败不提供伪成功入口。结果不明确先核验同一发布意图，不能重复发布、重复建资源或重复扣费。

正式会话固定已发布组合，不在对话中偷偷切换工具版本；新版本对后续新会话生效，旧会话继续使用其固定版本并受当前撤销规则约束。不能保留所需版本时明确要求新建会话，不能静默改绑。工具停用和权限撤销约束所有相关版本的后续调用，不能因快照固定继续越权；已发送的外部写操作无法承诺撤回。

修改工具先形成新草稿，经审核、授权与联合试用后发布。回退只能选仍获准运行的完整旧组合，并检查数据兼容；回退代码不回退业务数据或复活已撤销权限。工具产物被正式版本或保留中的会话引用时不能直接删除；停止临时任务只清理其计算资源，不删除用户源文件和业务数据。

## 5 五个阶段的完整体验

| 阶段 | 用户动作 | 必须交付的体验与结果 |
| --- | --- | --- |
| 创建 | 描述业务目标、提供资料，选择必要能力 | 明确服务谁、解决什么、怎样验收；自动带入合理默认值，只追问影响结果的必要问题 |
| 试用 | 测试对话、操作配套页面，查看回答依据和工具结果 | 聊天成果旁有明显的“打开预览”；显示当前草稿与测试数据范围；真正能交互，失败有原因 |
| 修改 | 通过聊天提出变化，必要时直接编辑或调进阶参数 | 沿用项目上下文，给出改动摘要；刷新或更新后验证新效果，不能把旧预览显示为新结果 |
| 发布 | 确认版本、访问对象、费用承担与数据影响 | 发布已验证版本；显示进度、地址和最终状态；代码或配置变化后旧确认失效 |
| 持续维护 | 查看使用反馈、异常与费用，再改进版本 | 新修改先进入草稿，原发布版本继续服务；可暂停、恢复、导出和受控删除；数据保留规则明确 |

### 试用必须真实而有边界

对话型应用提供真正的测试会话；有配套页面和后端的应用，启动首发支持范围内的实际服务。静态页面展示不代表后端、数据库和工具链已经运行。

测试会话使用独立的测试数据范围；有外部副作用的工具默认不调用生产写接口。若无可用测试环境，明确标记不可完整试用或在具备权限的情况下要求一次具体操作确认，不能用模拟结果冒充真实执行。

预览应区分加载、启动、就绪、更新、失败和已停止。闲置停止只回收相应运行资源，不删除持久文件和业务记录；重开后说明哪些临时测试状态不会保留。

### 上下文必须可理解

项目切换时显式切换文件、知识、工具与运行对象；不同项目或不同用户不能意外共享上下文。普通聊天转入项目时允许用户选择相关内容，不默认把全部历史、附件和密钥传入 Agent。开发会话不自动成为已发布应用的知识库。

### 界面为任务服务

保持聊天主界面稳定，以项目名称、草稿/线上状态和少量明确动作提供方向。文件、代码、工具细节和日志按需展开；不能同时堆满文件树、部署卡片和监控面板。模型与进阶设置可达，不强迫普通用户先配置 Agent 才能开始。

“打开预览”“继续修改”“确认发布”“访问应用”要易于发现。安全地重试、取消、查看费用和导出均保留直接操作，不强迫所有动作通过聊天。中文、亮暗主题、窄屏和键盘可用性属于验收范围。

项目界面按用户任务组织，不按后端模块堆放卡片。顶部清楚显示项目名称、用途、当前版本/草稿状态与下一主要动作；知识、技能和工具按需展开，发布、成员和费用在相应阶段管理。同一表单的字段、保存状态和操作必须形成可理解整体，不能让用户猜测按钮作用于哪个框。

少用介绍性文字补救导航。创建者从“描述想实现什么”开始，已有项目从“继续改进 / 试用 / 运行中的应用”开始；应用使用者直接进入被授权应用。对话助手侧重资料与能力，代码应用侧重文件、交互预览和部署运行，不强制共用一整页配置表。普通界面使用业务能力名称，Prompt/Tool/Skill/RAG 参数放入高级设置。隐藏技术参数不能隐藏缺失能力、授权范围、费用、失败和数据删除影响。

侧栏用于切换与摘要，复杂配置使用有明确返回路径的编辑区域；保持主聊天与已有上下文稳定。使用统一字体层级、紧凑列表和明确选中态；不能靠放大字体、巨大卡片或嵌套边框表达层级。首次创建、无知识、试用失败、存在未发布修改和已上线等状态各有明确下一步；长期资料保留与临时运行状态分开显示。

### 创建者与受邀使用者的界面和权限

| 能力 | 创建者对自己的项目 | 受邀使用者对该应用 |
| --- | --- | --- |
| 使用正式助手 | 可使用，费用归属明确 | 可在获授权范围使用；不继承开发权限 |
| 管理自己的会话 | 可管理 | 可重命名/删除自己的会话；不等于改应用标题或删除应用 |
| 查看知识依据 | 按实际授权查看 | 仅查看被授权的来源，不默认浏览全部原文和文件 |
| 修改应用标题、指令、模型、Skill、工具 | 可修改草稿，重新验证后发布 | 不允许，包括通过原生构建器和直接接口修改 |
| 删除、复制配置、重新分享、修改访问和预算 | 按所有权及操作规则执行 | 默认不允许；另行授权的协作/模板复制不属于首版使用权 |

受邀入口应表现为“别人分享给我的应用”，而不是“我创建的智能体”。技术上复用原生智能体执行器时，运行入口由平台管理，不能为方便接线授予成员 OWNER/EDIT/DELETE/SHARE 权限。原生构建器、列表、导入导出、复制、分享、编辑和删除接口均须遵守同一边界；仅隐藏按钮不构成修复。

同一账号创建自己项目的权利不因其受邀身份被关闭。管理员的配置/审计权也不自动赋予任意读取私人对话的权限。未来协作者角色须显式授权，不能把“受邀使用者”解释为编辑者。

## 6 不得牺牲的产品规则

1. **真实反馈。** 流式展示可公开的回答和实际执行进度，重复工具信息折叠；不展示模型私密推理，不以假进度或循环动画掩盖停滞。
2. **明确失败。** 说明已完成什么、未完成什么、线上服务和数据是否受影响、用户下一步能做什么。原始日志是补充，不是唯一反馈。
3. **有限执行。** 自动修复、模型调用和工具执行都有时间、次数、并发与预算边界；耗尽后保留成果并停止，不无限循环消耗。
4. **状态可信。** 普通查询超时保留上次确认状态并重试；写操作结果不明先核验，不能直接重放或伪称失败。刷新/断线不能重复创建任务、订单或发布。
5. **版本一致。** 试用结论绑定对应版本；发布同时检查代码与 AI 行为配置变化。不能只核对源码而漏掉 prompt、知识、模型或工具权限改变。
6. **数据持久。** 任务失败、停止服务、删除聊天或套餐到期都不等于授权删除数据。删除须说明范围、依赖、保留期和后果，并确认实际清理结果。
7. **恢复有边界。** 源码恢复、应用版本回退和业务数据恢复分开处理。新版本失败尽量保留旧版本；不兼容的数据变更须有明确迁移及恢复方案。
8. **权限贯穿。** 身份、文件、检索、工具调用、发布、应用访问与账单均在服务端校验；界面隐藏不构成授权。工具返回和知识文档都是不可信输入，不能自行扩大权限。
9. **成本可解释。** 开发、试用、线上应用调用和运行消耗可区分、可归属。模型额度不足与磁盘不足分别说明，不用一个模糊的余额替代所有权益。
10. **可退出。** 提供首发承诺范围内的配置、源码和业务数据导出；说明不能导出的第三方依赖及迁移步骤，不承诺所有应用完全离线可用。

## 7 从功能到商业应用的推进顺序

以下是有先后依赖的阶段门槛，不是工期承诺。访谈可与工程修复并行；产品团队未通过阶段评审，不把下一阶段目标当作已完成。

| 阶段 | 核心问题 | 必须完成 | 退出门槛 |
| --- | --- | --- | --- |
| P0 现状与范围对齐 | 已有能力究竟能支撑什么 | 盘点代码、部署、UI 和验收证据；确认首发支持矩阵、项目/Agent/会话关系、复用与缺口；整理原型 | 每项承诺有实现位置或明确缺口，首发业务脚本和验收方式确定；不再以组件已部署认定功能完成 |
| P1 首个 AI 应用闭环 | 用户能否独立交付一个助手 | 以知识助手验收创建、授权资料、试用、修改、固定发布与返回维护；同时验证无知识助手不被强制上传或编程 | 重复完成五阶段流程；使用者不进入该应用的开发管理入口，直接修改接口也被拒；知识权限、版本和费用归属正确，界面可理解 |
| P2 从回答到办事 | 助手能否正确执行实际业务 | 在 P1 上增加受控业务读写能力，以创建/查询工单及必要页面、存储作为首个验收样板；不把工单强制到所有项目 | 样板完整任务验收通过；重复提交不重复写入、越权读取被拒、未知结果先核验；修改发布后原记录保留 |
| P3 可持续使用的内测版 | 用户回来后是否还能放心使用 | 项目状态、线上反馈、用量预算、异常恢复、版本回退边界、导出和运维处理流程 | 达到第 8 节内测门槛；真实数据前完成独立备份恢复；用户可以不依赖开发者后台修补完成任务 |
| P4 受控商业试点 | 有人愿意付费且平台能履约吗 | 明确套餐、真实支付与权益到账、对账退款、访问与数据条款、支持渠道；邀请小规模同场景团队 | 真实付款和财务核对完成；试点观察到持续任务使用、返回修改及可解释的成本；阻塞问题有处置和退出方案 |
| P5 扩大商业应用 | 能否可预测地服务更多客户 | 根据留存与成本优化引导、支持和容量；逐步增加相邻场景或团队能力 | 达到试点评审确定的留存、毛利、支持负担和容量指标，再扩大范围；不得凭演示成功直接扩张 |

P1 是 P2 的一个可独立验收的纵向切片，不是先做一个没有发布和维护能力的配置页面。已有工单能力可以复用，但不能跳过 AI 回答、知识权限和最终用户访问验证。P0 若发现已有能力足够，可用证据直接通过对应条目，无须重复造轮子。

## 8 质量门槛和证据

以下数值是首版的**内部验收目标**，不是行业标准、线上实测成绩或 SLA。P0 固定测量方式及负载条件；若因实测需调整，须在测试前记录理由和影响，不得失败后悄悄降低门槛。

| 维度 | 内测目标 | 记录方式 |
| --- | --- | --- |
| 请求反馈 | 点击提交后 1 秒内出现已受理、校验失败或明确的连接状态 | 记录从用户操作到界面反馈的时间，不把已受理算作模型回答 |
| 模型交互 | 已就绪环境的普通测试对话，首次有意义回答 p95 不超过 10 秒 | 单列排队、冷启动、检索与模型等待；失败/超时不从样本中隐藏 |
| 执行透明 | 超过 10 秒未获得新进展时解释正在等待什么；到任务期限必须终结或进入明确核验状态 | 不伪造进展，不要求每 10 秒必须产生一条工具输出 |
| 核心交付 | 每条已承诺场景先连续 3 轮完整成功，再积累至少 20 次完整尝试，成功至少 19 次 | 覆盖至少 3 个独立测试身份、2 个测试日；记录失败和所有人工干预，修复后重新回归 |

| 重要保护 | 越权访问、重复扣费、重复业务写入、数据误删与版本错发用例必须全部通过 | 发现任一问题阻止相应试点，不用平均成功率抵消 |
| 无协助使用 | 至少 3 位目标用户各自完成首次使用及一次返回修改，无开发者后台修补 | 记录需要解释的位置、放弃原因与耗时；访谈口头认可不算完成 |

### 产品理解与权限补充门槛

以下门槛与上表并行，不降低原有性能、重复次数与数据保护标准：

- 创建者无口头指导即可辨认当前项目、草稿与线上版本、下一主要动作、保存是否成功和费用承担者；完成无资料助手路径时不被迫上传、编程或部署。记录误点、求助和放弃，不以开发者熟练点击代替易用性。
- 使用者可以独立打开受邀应用、对话和查看授权依据；不能在构建器中管理该运行入口。直接请求编辑、删除、复制、分享与敏感配置导出也必须拒绝；同时验证其自身项目仍可创建和管理。验收包含已有入口迁移，不能只测试新账号。
- 文件列表能解释资产来源、所属项目、知识/发布引用和容量；同一资产从不同入口打开一致，删除和复制影响可预期。检查中文、亮暗主题、窄屏、键盘、行高、按钮分组与焦点恢复，不能只证明页面能打开。
- Skill 导入须分别验证纯指令、资源引用、缺少依赖和未授权工具的行为；导入不扩大权限，更新不改变已有发布版本。将这类能力列入支持矩阵后才要求上线交付，不把计划写成现成功能。
- 嵌入组件或模型升级须有新旧索引、引用、检索效果、授权、计量和回退证据；未实施升级时标记未验证，不把“镜像可以更新”当作迁移完成。

测试身份只能使用当前已授权账号或专门获批的测试身份。当前只有一个指定验收账号可做用户流程时，先完成其回归，多身份门槛标记“未满足”；不得擅自使用其他真实账号，也不得宣称通过。

20 次尝试仅提供小样本回归证据，不能证明生产 95% 可用性。复杂生成、构建和预览冷启动单独报告 p50/p95、超时率和重试费用；P0 为支持矩阵中的场景设定期限，不承诺所有项目统一秒开。

固定异常矩阵至少包括：模型超时/限流/额度不足、知识索引失败、工具超时与未知写入结果、预览启动失败、构建失败、部署未就绪、浏览器刷新/断线、重复点击、容量不足、权限撤销、修改后重新发布及运行环境重启。检查是否保留成果、重复执行、影响旧版本和完成清理。

每次验收记录：代码与镜像版本、环境和账号类型、场景与输入数据、操作步骤、预期/实际结果、耗时、用量、失败次数、人工干预、证据位置和遗留问题。凭据、私人对话及真实客户数据不写入报告。

### 自然语言创建与能力目录的新增验收条件

- 用户不手写 Prompt、工具定义或 Skill 配置，即可从自然语言生成草稿、试用、修改并发布一个受支持助手；同时验证无知识、知识检索和需要连接授权的路径。
- 管理员登记并审核一个合成工具/Skill 后，符合条件的创建者能通过自然语言选用；未审核、未授权、不兼容和停用能力不能被配置成可执行。既有 MCP 页面存在不等于此链路通过。
- LLM 返回不存在的能力 ID、过期版本、超出权限的参数或缺少依赖时，服务端拒绝或形成明确待处理项；只隐藏前端选项不能算通过。
- RAG 只列出并检索该用户和项目获授权的资料；上传普通文件不自动授权检索，索引未就绪不伪称可用。
- 试用验证真实执行结果与引用；缺少凭据不自动调用生产写接口。取消、失败、重试不重复计费或重复业务写入；模型调用本身也受创建过程的预算和次数限制。
- 新版本发布可追溯能力目录与知识版本；正常能力升级不改变旧应用，撤销/停用对旧应用后续请求生效。关键权限、引用和费用检查需覆盖直接接口。
- 代码应用单独验证具有业务登录与数据库的交互试用、部署、运行观察、修改后数据保持；不能用纯聊天测试代替代码应用交付验收。应用内部账号不继承星桥开发权限。
- 自动开发工具必须验证目录缺口识别、受限开发、规则/人工审核、用户授权、联合试用与版本发布；覆盖未经审核、替换构建产物、超范围访问、撤销、旧版会话、联合发布部分失败及未知写入。完整目标用例见[总体设计的验收清单](overall-design.md#9-验收与交付边界)。仅生成代码或工具单测通过不能记为助手能力交付。

上述为新增目标门槛，不是本次文档更新的测试结果；与既有重复验收、性能、恢复和真实用户无协助使用门槛共同生效。

## 9 商业与运营原则

### 收费对象与价值

优先向创建并维护应用的个人/团队收费；受邀使用者默认无需购买创建套餐。首版线上应用模型调用由应用所属账户承担并显示归属；若未来支持使用者自带额度或转付费，必须单独设计告知、授权和防重复扣费。

套餐分别说明模型费用额度、持久存储、运行规格、可发布应用数、并发与执行限制、访问与支持能力，以及有效期。模型价格不同，不用固定 Token 数冒充精确的消费额度；如展示 Token 估算，标明模型和估算口径。

人民币售价、授予用户的模型预算、LiteLLM 美元计量、平台供应商实际成本是不同概念。例如售价 10 元、模型预算折合 5 元，不能显示成给用户充值了 10 元模型额度。订单固定成交权益和折算规则；目录改价不追溯改写已成交订单。注册赠额沿用有效配置，发放必须幂等，不能因升级或重新登录重复赠送。

### 从模拟交易到真实交易

虎皮椒 V3 本地模拟器是接口与故障测试工具，不能作为真实支付验收证据。真实收费前验证服务端金额与签名、重复/乱序/延迟通知、订单查询核验、权益开通重试、到账对账、退款与权益处理、过期和欠费处置。客户端跳转成功不代表支付成功，支付成功也不代表资源已经开通。

测试订单不能混入实际收入。真实交易试点需商户条件、明确费用授权及相应用户确认；不能把历史的模拟支付授权扩大为任意真实扣款授权。

### 真实数据与公开服务

当前单节点、本地恢复演练和内部域名访问不能证明生产高可用、公网可用或整机故障可恢复。客户真实数据试点前，必须有独立于集群主机的备份目标、明确恢复点/恢复时间目标及演练证据。缺少条件时保持合成数据内测，不用文本承诺替代。

公开服务前完成适用的身份与滥用防护、TLS/域名访问、知识与工具权限、密钥保护、数据保留与删除规则、隐私告知和支持流程。具体商业/法律条款在真实经营范围确定后专项核验，本文不代替该审查。

### 市场验证

收费围绕创建与维护应用产生的价值，资源规格用于说明成本和边界。注册赠额是体验预算，不是价值已经实现。不得为纯聊天/知识助手人为增加独立服务部署以制造收费项；代码应用的运行资源应说明对应任务、使用量和停止后的数据保留规则。

商业假设按顺序验证：目标客户是否反复遇到同类任务 → 能否无协助获得可交付结果 → 受邀使用者是否持续使用 → 创建者是否返回维护 → 是否愿意付费且支持成本可承受。早期优先验证一个任务群，再考虑服务团队和相邻场景，不把模板数量或组件数量当作市场拓展。

试点重点观察：首次独立交付率、首次价值时间、每周实际完成任务的应用数、创建者返回修改、最终用户持续使用、真实付费与续费、模型和运行成本、退款及每客户支持耗时。

不以注册数、累计聊天数或一次性满意评价代替价值验证。试点前固定观察周期与继续/停止条件；访谈、真实费用授权和商业判断由产品负责人参与，AI 不能编造客户意见或代替购买意愿。

## 10 后续 AI 的执行协议

### 每次任务开始前

1. 阅读本文及相关仓库 AGENTS.md，确认当前阶段与用户最新指示；用户尚在讨论时不自行恢复编码。
2. 检查当前代码、未提交改动与相关验收记录，区分计划、实现、部署和真实使用四种状态。
3. 用一句话写清本次改善哪类用户的哪段完整任务；列本次范围、暂不做的内容、依赖和可观察的通过条件。
4. 优先复用已有身份、项目、权限、用量与发布机制；不要为一个 UI 入口另造一套任务或计费系统。

### 开发和测试时

- 按纵向用户任务交付，不能只完成后台接口或一个配置页就称为产品完成。
- 每项改动同时检查普通用户入口、管理员职责、费用归属、权限、持久数据、失败/取消/重试/恢复和已有项目兼容性。
- 后端以 Python/Go 独立服务承载业务，浏览器为主。未来 Tauri 仅承担 GUI 和独立 Sidecar 生命周期，不把复杂业务塞进 Rust 主进程。
- 新能力先说明技术契约、状态与迁移影响，再实施；保留既有安全与租户边界，不因赶功能移除。
- 自动化测试可以用脚本；交付验收必须覆盖真实产品 UI。直接改数据库、绕过界面或人工补资源只能用于明确诊断/修复并记录，不能算“用户独立跑通”。
- 不覆盖用户工程与其他未提交工作，不擅自删除数据，不通过未经批准的账号扩大测试。
- 不声称底层组件支持某能力就等于本产品支持；必须验证接入后的权限、成本、错误处理和实际结果。
- 先判断所选任务是否需要知识、Skill、编程或服务部署，再选择组件；不能以已有 OpenHands、存储或售后样板反推所有用户的流程。
- 权限测试须覆盖所有可达产品入口及直接接口，尤其原生 LibreChat 构建器与平台发布入口之间的边界。新发现的前序缺口要追加到阶段证据，不能以原有通过记录覆盖。

### 每次交付后

按以下格式简要记录并报告：

```text
产品阶段与本次用户任务：
用户可见变化及入口：
实现 / 已部署 / 已通过真实 UI 验收的范围：
测试版本、环境、轮次、结果与证据：
人工干预、失败及尚未通过的门槛：
数据、权限、计费与兼容性影响：
下一步唯一最高优先级任务及依赖：
```

若主流程未通过，优先解决断点，不转去扩展新功能。没有证据不能写“完成”“稳定”“生产可用”；模拟器、单元测试、单账号 UI 成功、真实客户试点分别陈述。

### 方向变更

新增主场景、改变收费对象、扩大公开范围或引入新的核心平台，属于产品决策。先给出用户价值、代价、替代方案和验收方式，再取得明确方向并更新本文。普通实现细节由开发者在已授权范围内判断，不反复要求用户审批。

### v1.5 项目合并与用量要求

原生项目是唯一用户入口。项目中的创建、修改与私人试用会话归入该项目；普通聊天仍可独立，受邀使用会话不能因此获得创建者项目权限。个人空间唯一且持久，保留在个人菜单。项目页顶部显示明确标注的账号级资源摘要：逻辑存储已用/有效上限、模型实际支出/已分配额度及累计实测 Token、已部署应用/有效上限。按美元预算计费时不把估算 Token 当成固定套餐上限；未知、部分计量、过期数据须明确标识。删除导航项目不得连带删除文件、助手、知识或线上应用。

智能体项目另有明确确认的自助删除流程。确认前展示撤销范围和保留资产，确认后撤销发布与分享，清理草稿、试用和项目专属知识。仅清理经创建回执确认归属且未被其他运行资源使用的专属根目录及其文件，旧项目复用的目录保留。独立或仍被引用的知识库、历史会话和计费记录保留。失败后从已持久化的步骤继续。

代码应用项目也支持自助删除。确认前按部署、域名、数据库、镜像和文件展示清理范围。先撤销应用路由并确认运行资源已清除，再删除归属已核验且未共享的数据库。用户可同时清理经创建回执确认的专属目录。旧目录、共享或归属不明的资源、Harbor 镜像、历史会话及计费记录保留。失败可从已完成的步骤继续，资源归属出现冲突时进入待核验。

自然语言创建仍须统一草稿、能力目录与服务端授权，项目合并不代表这一能力已完成。
