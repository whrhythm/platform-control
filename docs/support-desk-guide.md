# 售后工单业务样板

## 使用流程

在 LibreChat “我的空间 → 项目”选择“从售后工单样板开始”，填写项目名称。系统登记一个新项目和新目录，不移动旧文件，不自动发布。点击“准备项目与数据库”后将样板源码复制到这个目录，并按现有套餐额度申请项目数据库；中断可重试，已改动的文件不会被初始化覆盖。

进入“预览并验收”，在示例页面登记一条工单、分配负责人、更新状态并筛选。逐项确认后保存预览验收。预览运行在隔离 iframe 中，禁止联网，只操作浏览器内的示例记录。它不是应用后端测试，不写入真实工单，不证明真实登录、导出权限或持久保存已经通过。

数据库就绪后选择“前往应用发布”，沿用现有发布确认和应用入口。应用状态为运行中时打开地址；在项目页展开“应用管理员登录”，单独查看应用用户名和口令。该账号属于工单应用，不是平台账号，也不是集群账号。

管理员进入应用后选择“邀请同事”，可生成处理人或只读邀请。复制链接交给同事，平台不自动发送邮件。邀请七天有效且只能使用一次；链接中的一次性凭据位于 URL fragment，避免作为普通请求路径发送。接受邀请的人自行设置应用用户名和口令。

| 应用角色 | 查看和筛选 | 登记、分配、更新 | 导出 | 邀请 |
| --- | --- | --- | --- | --- |
| 管理员 owner | 是 | 是 | 是 | 是 |
| 处理人 | 是 | 是 | 否 | 否 |
| 只读 | 是 | 否 | 否 | 否 |

这些角色均不获得编程平台源码、模型额度、数据库管理或发布权限。列表最多显示 500 条，导出最多 5000 条；页面提示截断，导出超限会要求缩小筛选范围。并发修改通过修订号检查，不静默覆盖另一人的编辑。

## 继续修改与数据保留

在编程设置选择这个已关联项目，再通过聊天要求修改。例如：“只把 settings.json 的 title 改为售后工单·回访版，保留其他字段，不修改数据库和账号，不自动发布。”也可在文件编辑器修改。

重新打开预览可看到当前页面与名称；修改源码后须重新保存预览验收。验收绑定完整构建源码指纹，发布请求会冻结该记录，构建完成后用实际源码指纹核对，不把旧验收自动套用到新代码。

业务数据保存于既有共享 PostgreSQL 中该项目的独立数据库。构建只打包源码；启动只创建缺失表和首次管理员，不清空工单、不重置账号。再次发布使用原数据库连接身份，应用源码恢复不等于业务数据恢复。将来修改表结构仍需要专门设计兼容迁移，不能依赖删表重建。

## 实现与权限边界

- `business_templates` 表保存项目初始化状态、文件摘要、加密的首次应用口令及人工预览验收。迁移为 `0022_business_templates`，非空时拒绝直接降级删除。
- `POST /internal/v1/workspace/business-templates` 使用请求 UUID 和当前用户身份确定项目 ID，重复请求不创建第二个项目。
- 项目 `prepare` 接口使用既有文件服务与数据库申请逻辑。目录和文件只以不覆盖方式创建，重试核对已有文件摘要，不恢复或清理用户改动。
- 项目 `preview` 从同一份构建快照读取页面和应用名称，返回源码指纹；页面运行在无同源权限、无网络、无表单外发的 iframe 中。
- 项目 `acceptance` 检查当前源码指纹和修订号，记录用户手动确认；不是 AI 自动业务验收。
- 项目 `access` 仅所有者可调用，禁止缓存并记录审计。口令不写入聊天、业务日志或源码；源码仅含加盐 scrypt 摘要。工单账号、会话和邀请持久保存于项目数据库。
- 样板资产位于 `control_plane/templates/support`，复制后属于用户工程，不随平台升级强制覆盖。基础镜像固定摘要、包含锁定依赖，构建不必重新下载 Python 库。
- 开关 `PLATFORM_BUSINESS_TEMPLATES_ENABLED` 默认 false；LibreChat 从后台目录发现是否启用，不改变普通聊天模式。

## 验收范围与限制

本地测试已覆盖初始化重试、文件冲突不覆盖、源码变化拒绝旧验收、所有者访问、工单角色权限、重复邀请、并发编辑冲突、CSV 公式转义，以及应用重启后工单和账号保留。完整后端回归 307 项通过、34 项条件跳过；临时 PostgreSQL 测试 21 项通过，其中包括工单业务流程和新应用实例读取原数据库。

2026-11-06 已完成真实浏览器完整验收。平台全程使用此前指定的账号；处理人和只读人员是这个工单应用内的合成测试账号，不是新增平台用户。用户操作通过 LibreChat 和工单应用页面发起，未用直接写 SQL 代替操作。

| 流程 | 实测结果 |
| --- | --- |
| 创建项目与准备 | 新建独立目录和项目数据库，保留已有空间文件 |
| 示例预览 | 登记、分配、更新状态、按负责人和状态筛选；保存当前源码指纹的人工验收 |
| 首次发布与失败恢复 | 首个基础镜像展开层数过多导致构建临时空间耗尽；界面显示失败原因，失败 Job/Pod 被回收，文件与数据库保留。替换专用运行镜像并从页面重新发布后成功，未扩大套餐配额 |
| 真实业务 | owner 登记工单、邀请处理人；处理人接受邀请后完成分配、解决和筛选；owner 导出 CSV |
| 访问权限 | 只读用户没有新增和保存入口，导出接口返回 403；处理人同样不能导出；匿名访问工单接口返回 401 |
| 聊天修改 | OpenHands 在已关联工程中仅修改 `settings.json.title`，验证 JSON 可读取；聊天显示完成结果 |
| 再次发布 | 重新预览验收、发布同一应用；原访问地址、工单 ID、描述、负责人、已解决状态和三类账号登录会话均保留；页面确认线上源码与验收指纹一致 |
| 文件编辑与窄屏 | 从既有文件编辑器修正表格窄屏显示，重新验收并发布；表格可以横向查看，页面本身没有横向溢出，窄屏能打开工单详情，原记录再次保留 |
| 聊天与主题 | 保留现有聊天布局、文件和应用入口；亮色、暗色、390px 窄屏均检查，新增内容集中在“项目”页与预览弹窗 |

预览浏览器检查额外确认：允许页面内表单交互，但不能访问父页面或向外联网；CSP 继续禁止表单对外提交。预览验收与真实业务验收分别进行，不把示例页面当成后端测试。
