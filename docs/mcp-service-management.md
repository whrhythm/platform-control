# 管理员 MCP 服务目录与凭据隔离

本版将 DeepWiki 固定目录扩展为数据库管理的服务目录，已有 DeepWiki 选择保持兼容。管理员可通过界面添加其他公网 HTTPS Streamable HTTP MCP 服务，无需改代码或逐个增加共享执行器的公网出口。

## 管理流程

Platform Control → 平台管理 → MCP 服务目录：

1. **新增服务 / 保存草稿**：填写名称、HTTPS 地址、用途和数据去向。选择无凭据、平台专用只读凭据或用户专属凭据。
2. **检查连接与发现工具**：仅初始化会话和读取工具目录，不执行工具。固定本次解析的公网地址和工具定义指纹。用户专属连接使用管理员提供的临时测试 Token，不保存这个测试值。
3. **审核并发布**：工具默认不开放。管理员逐项选择只读或外部写入，检查参数结构与副作用并明确确认。服务自报的只读注解不作为授权依据。
4. **停用**：立即撤销后续调用；已发出的操作不能撤回。重新开放须重新检查与审核。
5. **归档**：停用并清除平台及所有用户关联凭据，保留审计与任务历史。

地址、凭据或配置修改会使服务回到草稿并撤销旧版本。连接检查也撤销旧版本，即使检查失败也不会继续开放旧工具。版本冲突需要刷新，不能覆盖另一位管理员的变更。工具目录新增项不自动授权；已批准工具定义变化时，实际调用前发现指纹变化就停止，要求重新审核。

## 用户流程

LibreChat → OpenHands → 编程设置 → MCP 工具：只有已发布服务可勾选。停用服务保留说明，方便用户取消旧选择；草稿、待审核和已归档服务不作为可用连接展示。

用户专属连接先填写该服务专用的 Bearer Token。保存后只显示“已配置”，不回显密钥；可随时撤销，包括服务已停用时。服务版本变化后需重新确认凭据。输入字段是一次性提交入口，不会从服务端读回原值，提交完成即清空。

每次外部调用在聊天里确认，包括只读调用。审批中展示目标地址、工具、参数和是否外部写入。计划/审查模式只能使用审核为只读的工具。选择及凭据版本随任务固定，切换或撤销凭据会停止旧任务继续使用。

## 凭据与网络边界

| 类型 | 保管与使用范围 |
| --- | --- |
| 无凭据 | 公开服务，不附加平台或用户认证信息 |
| 平台只读凭据 | 仅可发布只读工具；管理员必须确认该凭据可读取的数据适合所有可选用该服务的用户。不是租户私有数据隔离方案 |
| 用户专属凭据 | 以用户环境 ID + 服务 ID 为复合键，加密载荷再次绑定所有者、服务和凭据版本；不能由工具参数指定其他用户或借用另一连接的密钥 |

采用独立的 `PLATFORM_MCP_CREDENTIAL_ENCRYPTION_KEY`，不与模型密钥加密密钥混用。数据库、日志、审计及任务配置不保存明文 Token。平台密钥不返回管理员接口；用户密钥也不返回管理员或用户接口。归档清除密文；历史备份中的密文仍需按平台备份保留策略管理。

独立 **MCP Gateway** 只负责 MCP 传输：不挂载工程 PVC，不持有数据库、Kubernetes、Harbor、MinIO、LiteLLM 凭据，也不挂载 ServiceAccount Token。它临时接收本次调用所需的第三方凭据，完成后丢弃，不做跨用户 Cookie/OAuth 会话缓存。

API / 执行器通过内部 CA 验证的 HTTPS 加专用服务令牌访问网关。网络策略只允许这两个受管服务访问网关；网关只允许 DNS 和公网 TCP 443，禁止私网、回环、链路本地和集群服务网络。共享执行器原有 DeepWiki 公网出口被删除。

公网地址不仅在创建时检查：每次连接重新解析全部地址、拒绝非公网结果，固定连接到检查过的 IP 并保持域名 TLS/SNI 校验；运行调用还必须落在审核的地址集合。DNS 地址变化需要重新检查、审核发布。禁止跳转、代理环境变量、URL 中的凭据和任意端口。传输仍使用公共 CA，与内部服务专用 CA 分开。

## 执行与失败

只有审核工具能通过网关调用；输入按审核的 JSON Schema 验证。禁止外部 `$ref`、正则和超深超大结构等当前未支持的模式，界面会标记不可发布。工具描述和返回内容均属外部不可信数据，不会扩展文件、终端或部署权限。

读操作失败返回安全错误，不自动重放。外部写入无论严格还是工程自动模式都必须单次审批；超时、连接中断或上游报错不能证明没有执行，任务以 `agent_mcp_write_requires_review` 停止。用户需到目标服务核验结果；平台不提供“自动重试写入”按钮。用户停止或网络断开不能保证第三方已经收到的操作终止。

每次调用独立会话，默认 60 秒、每任务最多 8 次，沿用已有任务计数和聊天事件。网关最多 4 个并行请求；请求体 64 KiB、响应 256 KiB、文本结果 12000 字符。发现工具最多 80 个、分页最多 5 页；服务最多 30 个；单次审核最多 40 个工具。

## 接口及迁移

- `GET/POST /v1/admin/mcp`：目录和创建草稿。
- `PUT /v1/admin/mcp/{id}`：带 revision 修改；立即撤销旧版本。
- `POST /v1/admin/mcp/{id}/probe|publish|disable|archive`：检查、审核、停用、归档；管理员权限与审计。
- `GET /internal/v1/workspace/agent/mcp`：所有者视角目录和凭据配置状态。
- `PUT /internal/v1/workspace/agent/mcp/{id}/credential`：自己的凭据保存/撤销，secret=null 撤销；revision 并发检查。
- 网关 `/exchange` 仅集群受管服务可访问，不作为用户 API 暴露。

迁移 `0016_mcp_catalog` 新增 `mcp_servers` 与 `mcp_credentials`。API 有管理权限，执行器仅 SELECT；网关无数据库权限。需要独立 Secret `platform-mcp-secrets`，实际值不进入 Git。旧编程任务不会自动重放。

当前支持 Bearer Token 与无凭据的公网 Streamable HTTP；OAuth 授权跳转、SSE 旧协议、内网服务、任意 stdio 暂不支持，不应把它们填入当前入口。相关原理遵循 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 和 [MCP 安全实践](https://modelcontextprotocol.io/specification/2025-11-25/basic/security_best_practices)。
