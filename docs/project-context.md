# 项目入口与上下文

## 用户流程

“我的空间”增加“项目”页签，文件、应用和聊天入口保留。先在“文件”中选择或创建目录，再在“项目”中关联它，填写项目名称与一句话目标。关联只建立元数据，不移动文件，不创建额外磁盘，不启动 Agent，不发布应用，也不修改当前对话的编程设置。

项目详情汇总同一用户、同一目录的最近 30 轮编程任务、各轮人工验收结果和最近发布信息。可以打开原对话继续，或跳回文件、应用页签；嵌套目录会完整保留。多个对话可以属于同一目录；历史任务不会迁移或改写。

首次编程仍从模型菜单选择 OpenHands。“编程设置”新增已关联项目选择器，选中后保存设置，再在聊天中发出需求。普通聊天不会因浏览项目而切换为编程。项目目标是用户整理信息，不自动替代发给 Agent 的指令。

“核对文件”按需比较当前构建源码与最近成功发布的源码指纹，并显示核对时间。尚未核对、无法核对、没有可比较版本和代码发生变化分别显示；不能用最近发布成功推断当前文件已经发布。核对之后的文件变化需要再次核对。与发布溯源一致，此指纹不包括依赖缓存，也不代表业务数据库状态相同。

## 接口和一致性

- `GET /internal/v1/workspace/projects`：读取已关联项目。
- `PUT /internal/v1/workspace/projects`：按 `path` 保存 `name`、`goal` 和期望 `revision`。一个用户同一路径只有一个项目；相同保存重试返回已有结果，旧修订冲突不覆盖新内容。
- `GET /internal/v1/workspace/projects/{id}`：汇总项目资料、最近任务与现有应用，不转发隐藏系统提示或执行日志。
- `GET /internal/v1/workspace/projects/{id}/source`：只读核对构建输入。存在活动编程任务时拒绝核对，文件读取失败不会删除项目或把旧状态标为成功。

LibreChat 使用既有登录身份代理接口。用户身份不从请求正文取得，查询同时校验所有者。目标加密存储；审计只记录项目 ID 和修订。项目目录关联后不可通过编辑元数据改路径，目录改名或删除不会自动挪动业务资源。

元数据上限默认每用户 100 个，由 `PLATFORM_WORKSPACE_PROJECTS_LIMIT` 配置。它不是付费套餐的发布应用数量，也不新增磁盘权益。现有文件、任务、套餐与应用表不迁移。

## 部署边界

新增 Alembic `0020_workspace_projects`，只创建项目元数据表及唯一约束。迁移先执行并授予 API 必需权限，再更新要求新版本的 API，最后部署 LibreChat。其他工作器不读写该表，不变更 CapacityPlan 或 AgentConfig；其镜像无需因为本次元数据变更同步替换。降级前若表内已有项目资料会拒绝删除。

本批不包含完整需求看板、无限任务历史、自动业务验收、项目多人协作或完整发布历史。关联目标目录不意味着文件被锁定，原有文件编辑、源码恢复点和发布权限继续生效。

## 验证记录

2026-11-06 已通过真实浏览器验收，沿用指定验收账号和既有测试工程，没有创建新用户或移动文件：

1. 关联既有目录，核对源码与既有最近成功发布一致；刷新后名称、目标、目录和历史任务仍可读取。
2. 点击“打开文件”自动展开目标目录；第一次验收发现目录折叠，修复后重新通过，并增加嵌套目录回归测试。
3. 打开原对话，在编程设置选择同一已关联项目并保存，发送创建 `project-context.txt` 的要求。OpenHands 在同一目录创建文件并用 Python 读取，输出预期内容。
4. 项目页识别构建源码变化；进入既有应用执行“更新发布”，实际访问服务返回既有页面内容，项目再次核对与新发布源码一致。
