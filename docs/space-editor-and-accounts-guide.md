# 个人空间编辑器、代码运行与用户管理

## 普通用户：文件预览与编辑

在 LibreChat 左侧点击「我的空间」。默认宽度沿用左侧展开栏的宽度，仍可拖动分隔线调整。聊天保持在中央，空间用量保持可见。

点击文件名打开预览窗口。文本文件使用 Monaco 编辑器，显示行号，并按扩展名提供语法高亮；点击铅笔切换编辑，再点击「预览」可以检查当前内容，两种模式共享同一份编辑内容。保存后重新读取文件。铅笔只显示图标，保留可访问名称和提示。

- 未保存时关闭窗口会询问是否放弃；切换预览不会丢失修改。
- 保存沿用打开文件时取得的版本。若 OpenHands 或其他窗口已经修改该文件，保存会提示冲突，不静默覆盖。
- 默认预览/编辑上限为 1 MiB，可通过 `codechat.filePreviewMaxBytes` 配置；UTF-8 文本可编辑，支持的图片提供图片预览。其他二进制文件继续使用下载。
- 编辑器及语言服务随应用打包，在打开文件时按需加载；不从公开 CDN 下载编辑器，也不向公开服务发送代码。
- 亮色、暗色、高对比主题跟随 LibreChat。主聊天布局和已有文件树操作保留。

应用卡片中的 CPU、内存和数据库用量使用相同内边距、字号、进度条及「已用/上限（百分比）」形式。数据库仍归属于使用它的应用，不增加独立数据库导航。

## 普通用户：运行代码

普通聊天生成 Python 等受支持的代码块后，点击代码块旁的「运行代码」。请求由 LibreChat 后端提交到独立 CodeAPI 服务；执行输出显示在聊天中。

这里有两种用途不同的入口：

| 入口 | 文件与用途 |
| --- | --- |
| OpenHands 编程助手 | 在个人空间中创建、修改、测试项目，构建并发布应用 |
| 聊天代码块「运行代码」 | 临时计算和试验；独立执行环境，不直接挂载个人项目盘 |

临时代码结果保存在独立 MinIO bucket，采用一天生命周期和 2 GiB 服务总上限。清理异步执行；需要保留的结果应及时下载并上传个人空间。该服务临时存储不冒充个人项目磁盘用量。当前未将代码执行资源纳入各付费套餐的独立计费规则。

编程设置保留模型、工作方式、项目目录、审批方式和 MCP；不再显示执行记录。任务审批、进度及结果仍在聊天卡片中显示。

## 管理员：用户与资源

使用有 `platform-admins` 权限的账号登录 Platform Control，进入「用户与资源」。

1. 「登录账号管理」支持搜索、分页和添加用户。初始密码至少 12 个字符。
2. 「编辑用户」可以修改用户名、姓名、邮箱、登录状态；密码留空表示保留原密码。
3. 取消「允许登录与使用平台」并保存，即禁用账号。重新勾选可以启用。
4. 用户首次登录后仍由现有幂等流程准备个人空间，不需要管理员重复创建磁盘。
5. 下方资源清单中的「查看详情」使用浮窗，支持关闭按钮和 Escape，并将焦点返回原入口。

超级管理员、平台管理员、服务账号、外部来源账号以及当前操作者受到保护，不能通过这个普通账号表单修改。没有硬删除用户或删除用户磁盘的入口。

禁用会立即建立平台访问限制；LibreChat 已缓存的账号状态默认最长保留 15 秒。编程任务在后续操作前重新检查限制。已经发出的模型请求或正在执行的一次外部操作可能完成，不能承诺瞬间撤回；已发布应用继续运行，已有文件、数据库和镜像保留。

如果保存显示「操作未确认」，先刷新核对，避免重复新增。远端写入可能已经完成；平台保留访问限制，直到管理员查看最新状态并再次明确保存。新增中断时可能留下一个禁用账号，可通过编辑补设密码并启用。所有写入记录开始、成功或待核验审计事件；密码不返回、不进入平台数据库和审计正文。

## 运维配置与恢复

- 数据库迁移：`0017_account_access`。迁移 Job 先执行，再更新 API。
- 身份服务凭据：`platform-system/platform-identity-directory`，仅 API 使用；专用 Authentik 角色只授予 `view_user`、`add_user`、`change_user`、`reset_user_password`，没有超级管理员权限。
- 该实现要求 Authentik 的 `platform-console` 使用 `hashed_user_id`，已核对其等于用户目录的 `uid`。变更 OpenID subject 模式属于身份迁移，不能直接切换。
- 目录令牌有效期一年；到期前在 Authentik 轮换并更新 Secret、重启 API。初始化脚本不会覆盖仍有效的现有令牌。
- LibreChat：`LIBRECHAT_CODE_BASEURL` 指向内部 CodeAPI `/v1`；`CODEAPI_AUTH_PROVIDER=librechat-jwt`，私钥只放在 `librechat-codeapi` Secret。
- CodeAPI：只信任配置公钥，核验签发者、受众、用户和有效期。当前上游模式拒绝旧 `X-API-Key`，因此没有设置虚假的 `LIBRECHAT_CODE_API_KEY`。
- 执行器通过专用设备插件请求 `starbridge.internal/kvm`，使用 libkrun 微虚拟机及 NsJail。无需给用户代码容器特权模式；OpenHands 的 Kata 机制保留。
- 部署清单和存储边界见 `ops/apps/codeapi/README.md`；任务与个人空间的持久存储由原有流程管理。

参考：[LibreChat Code Interpreter 配置](https://www.librechat.ai/docs/configuration/tools/code_interpreter)、[Code Interpreter 上游](https://github.com/ClickHouse/code-interpreter)、[KVM 设备插件](https://github.com/squat/generic-device-plugin)。
