## 关联契约

LibreChat 原生项目保存可选的星桥项目引用。用户不能通过通用项目编辑接口写入该引用；服务端只依据已认证身份向平台读取所有者资源后建立关联。旧项目首次接入采用稳定标识，并保证并发重试不生成重复项目；已有原生项目的名称、说明、文件、会话与指令不被导入覆盖。绑定了平台资源的项目暂不开放原生删除，避免失去维护入口；普通原生项目仍遵守既有删除保留会话语义。

原生项目指令用于项目聊天，助手草稿用于交付助手，两者不能默默互相覆盖。正式试用继续服务端固定快照，不因聊天归档而叠加原生项目资料或指令。受邀发布会话不自动导入创建者私人项目。

本轮不新增付费规则、不扩展工具执行权限、不把已有 RAG 资料重新导入。自然语言构建与统一高级草稿另列下一切片，不以导航合并代替。

### 用户可见变化及使用入口

1. 左侧会话栏的“项目”是唯一项目列表，旧星桥项目自动关联到这里；没有第二个星桥项目图标。列表与详情顶部显示个人账号所有项目合计的资源用量。
2. 点击“新建项目”，填写名称和描述。详情的“对话历史”沿用原生会话管理；“应用”接入助手或代码目录。普通“创建新对话”仍可在项目之外使用。
3. 助手路径：“应用 → 准备助手草稿 → 助手设置 → 试用助手 → 记录验收 → 发布 → 访问应用”。现阶段仍需手工维护助手草稿；不把这一步声称为自然语言自动构建。
4. 编程路径：“应用 → 新建文件夹或填写现有目录 → 关联文件夹”。随后从“打开文件”管理持久文件，从“应用”查看既有部署。OpenHands 和原代码部署链路继续复用，不因合并入口重建应用、数据库或磁盘。
5. 个人头像菜单中的“我的空间”保留唯一持久空间，在左侧展示文件，不跳走当前聊天。已关联应用资源的项目暂时禁用原生删除，避免误删维护入口；不会借删除项目销毁用户数据。

资源口径：磁盘使用现有逻辑容量汇总，模型同时展示美元已用/已分配与实际累计 Token，部署应用显示实际占用/有效配额。Token 没有跨模型统一换算的假上限；“已部署应用”不是项目数或助手数。采集不完整/失败有提示，刷新不把未知当零，不修改套餐与结算规则。
